## 二、顺手修掉的存量缺陷（不是新功能，是既有 bug）

1. **`v_work_item` 接错表**：CUSTOMER 分支 join 了 000033 的废弃 `customer` 表 → 客户节点在工作台**名称与区域为空**
2. **`v_work_item` 状态词不匹配**：视图判 `DONE`、代码写 `COMPLETED` → 节点**永远显示待办**（供应商侧被 inbox 的 UNION 掩盖，一直没暴露）
3. **供应商列表合同状态永不命中**：`supply_chain.go:332` 判 `DONE`，活路径全写 `COMPLETED` → 合同办完仍显示「未登记」
4. **下架不联动客户绑定**：`MarkSupplyOffline` **生产代码 0 调用** → 资源停供后客户绑定仍 `ACTIVE`，客户继续用已停供货源
5. **未配 webhook 时事件永不推进**：判空即 return，导致 `retry_count` 不涨、**DEAD 告警永不触发 = 监控失灵**
6. **集成测试假绿灯**：DSN 变量分散，未设置时 `t.Skip` 而 Go 显示 PASS → 统一为 `TEST_DSN`，跳过时打印「这条 SKIP 不是通过」

## 三、上线注意事项

### 必须做
1. **迁移**：本地/测试库需升到 **51**（000049 绑定表、000050 客户开通 + 视图修复、000051 `DONE` 词兼容）
2. **检查事件积压**：
   ```sql
   select count(*) from event_outbox where status='PENDING';
   ```
   G3-0 修正了"未配 webhook 就不消费"的行为。**若生产有历史 PENDING 积压且不想补发，先清一次**，否则配好 webhook 后会被当新事件投出去
3. **前端与后端同批上线**：B3a 的客户待办 deeplink 指向 `/internal/customers/:id`，该路由由 B3b 提供。**单独发布 B3a 会导致点击 404**

## 四、已知边界（刻意接受，不是遗漏）

| 边界 | 说明 |
|---|---|
| 客户侧合同授信**不走 F12 就绪** | `ResolveF12BusinessContext` 唯一实现是 `NativeSupplierF12`，非 SUPPLIER 直接 `ErrDependencyUnavailable`。客户侧改为**办理人确认 + 必填说明**，节点 note 里写明「F12 就绪能力待客户版 provider 就绪后启用」 |
| `onboarding_flow` **无任何外键** | `owner_id` 是多态字段，一个外键无法同时指向 supplier 与 customer_profile。**做"删除客户"时必须手工清三张表**，否则留孤儿 |
| 客户重名**查询判重**、非唯一索引 | 并发下可能两条同名。代价（观感重复）小于加索引的迁移风险；已有测试钉住"不产生脏数据" |
| 合同状态优先级 `办理中 > 已归档 > 未登记` | 有流程在办时显示「办理中」而非「已归档」——「已归档」是结案信号，会让人停止推进 |
| 客户仅支持 `COMPANY` | `INDIVIDUAL` 返回 400（个人主体缺 `mobile`/`real_name`，半成品入口比拒绝更糟） |
| 已开通模型数只算 `ACTIVE` | 禁用/待处理/停供不计入，与原型 `!archived && state==='已开通'` 一致 |

## 五、怎么验（给接手的人）

```bash
# 后端
cd model-pricing-backend
GOTOOLCHAIN=auto go build ./... && GOTOOLCHAIN=auto go vet ./...
GOTOOLCHAIN=auto TEST_DSN="postgres://app:<见 config.yaml>@127.0.0.1:5433/model_bss?sslmode=disable" \
  go test ./internal/infra/supplypg -run 'TestCustomer' -v   # 20 条真库测试

# 前端
cd model-pricing-web && npm run build
```

手工验收路径（约 20 分钟）：
1. 客户管理 → 新建客户（向导两步）→ 详情页 4 个 Tab
2. 「档案与办理」Tab → 发起开通 → 完成合同（必填说明）→ 完成配置（自动写绑定）
3. 回「接入模型」Tab → 应看到该模型与来源
4. 模型广场 → 某资源下架 → 客户详情「接入模型」应显示「来源待处理」（不是仍「服务中」）
5. 工作台 → 客户开通待办 → 应落到该客户「档案与办理」Tab
