## 0. 先搞清楚三件事，不然点两下就懵

### 0.1 这个原型是"三层身份、一套壳"

| 身份 | 怎么进 | 能干什么 |
|---|---|---|
| 内部员工（默认「陈乐 · 员工」） | 打开就是 | 维护模型、看供应商/客户、处理自己被派的待办 |
| 内部领导（「林舟 · 领导」「许澄 · 领导」） | 右上角身份下拉切换 | 比员工多一个「审批中心」入口；审批只能领导点 |
| 供应商 | 点顶栏「切换供应商视角」→ 手机号 + 验证码 `1234` 登录 | 只能看自己主体：申报 / 模型管理 / 账户设置 |

右上角那 5 个人是**演示成员**：林舟·领导、陈乐·员工、周宁·员工、许澄·领导、沈安·员工。
**同一个流程，换个身份看，能做的事完全不一样**——这就是原型的核心表达，别只用一个身份看。

### 0.2 数据只存在你自己的浏览器里

所有改动写 `localStorage`，**刷新还在，换浏览器就没了**。
要恢复初始状态：工作台底部有两个按钮 ——「重建供应商演示数据」「演示场景」。

### 0.3 三个你一定会踩的坑（先看，省得以为页面坏了）

1. **按钮点了没反应，多半是权限**。比如员工点审批、供应商点内部页面，代码里是静默 `return`，不给提示。**先看右上角你是谁。**
2. **"审批中心"只有领导看得见**。员工身份下导航就是 5 项（工作台/标准模型库/模型广场/供应商管理/客户管理），别找。
3. **供应商视角是独立的一套门**。它不继承内部登录，必须用手机号+验证码重新登。

## 1. 全链路一张图

```
① 建模型母表            ② 供应商报资源              ③ 内部审批 + 接入           ④ 客户开通
标准模型库               供应商视角·申报               工作台/审批中心              客户管理
＋新增模型              发起申报→新建模型申报          同意→生成接入流程           ＋创建客户申请
   │                       │  配置组(URL/Key)            │  账户与接口准备(运营)      │  客户名称
   │  官方参数12字段        │  添加模型(选标准模型)        │  资源配置(运营)           │  选报价单+模型
   │  价格计费条件          │  采购系数                   │  合同签署(商务)  ┐并行     │  指标要求
   ↓                       │  连通性/压力测试             │  授信开具(商务)  ┘        ↓
 官方参数表 ←──────────────┴─ 提交申报 ──→ 审批通过 ──→ 资源准入 → 模型广场可上架 → 客户接入模型
                                                                              （客户-模型-来源绑定）
```

**记住一句话**：模型是"标准品"，供应商报上来的是"某家在某节点的一手货源"，客户买的是"某个标准模型 + 指定货源"。
三层对象：**标准模型 → 供应资源 → 客户绑定**，中间靠两个动作串起来：**供应商接入流程**、**客户开通流程**。

## 2. 流程 A：内部端新增标准模型（模型母表）

**为什么先做这个**：后面供应商申报时，要从下拉里挑一个"标准模型"。没有母表，后面全空。

| 步 | 点哪里 | 做什么 | 会看到什么 |
|---|---|---|---|
| A1 | 左侧「标准模型库」 | 看顶部状态条 | 「上次成功抓取 / 最近尝试 / 自动抓取演示失败：未配置抓取接口」——说明官方资料目前是**人工维护**，不是自动抓的 |
| A2 | 右上「＋ 新增模型」 | 打开弹窗「新增标准模型」 | 12 个字段（见下） |
| A3 | 填表 | 厂商（下拉）/ 模型类型（文本·图片·视频·音频）/ 官方标准名称 / 官方 Model ID·版本 / 输入输出模态 / 容量与规格 / 核心能力 / API、限流与访问条件 / 发布日期·版本·生命周期 / 官方价格与计费条件 / 原厂官方资料 URL / 核验日期 | 价格是**多行**的：计费项 / 官方单价 / 币种 / 单位 / 适用条件，可「＋ 增加计费项」 |
| A4 | 底部「保存并留痕」 | 直接入库 | 表里多一行，且「操作记录」tab 会留痕 |

**关键理解**：这里**不走审批**（弹窗底部是「保存并留痕」，不是「提交领导审批」）。
页内文案写得很直白：「官方未披露参数明确填写"未披露"」——**"未核实"本身是合法值**，这栏留空是不允许的，要显式声明不知道。

## 3. 流程 B：供应商申报新模型（这条是你最该点透的）

### B1 进门

| 步 | 点哪里 | 做什么 |
|---|---|---|
| B1 | 顶栏「切换供应商视角」 | 页面变成供应商登录页 |
| B2 | 点页面里列的演示手机号（如 `18860000103`） | 自动填手机号 |
| B3 | 验证码填 `1234` → 点「登录」 | 注意：页面上下有**两个**"登录"，点下面那个提交按钮 |

登录后左侧导航只剩 3 项：**申报 / 模型管理 / 账户设置**。主体名显示在标题下（如「辰远计算 · 申报、测试与历史记录」）。

> 这里有个业务规则值得注意：页面写着「国内主体仅申报国内部署资源，…有过上架历史后主体属性锁定」。
> **主体属地一旦有上架历史就锁死**，不能改。这是合规设计，不是 bug。

### B2 发起申报

| 步 | 点哪里 | 会看到什么 |
|---|---|---|
| B4 | 「申报」→ 右上「发起申报」 | 出现两个入口：**新建模型申报** / 申报记录 |
| B5 | 点「新建模型申报」 | 打开编辑器（见下） |

编辑器分两块，**顺序不能反**：

**第一块 · 准入测试配置**（先有"门"，才能进"货"）

- 默认已有一个「原单组配置 · v0」，右侧「编辑」填 **URL / Key**
- 要多家供应商通道就点「新增配置组」
- Key **只在编辑时可填**，历史展示自动脱敏

**第二块 · 申报模型**（表格，一行一个模型）

| 列 | 怎么填 |
|---|---|
| 对应标准模型 | 下拉选，选项来自流程 A 建的母表（如 `DeepSeek-V3 · deepseek-chat`） |
| 接口模型 ID | 供应商自己的模型名 |
| 准入配置组 | 选第①块里配好的组 |
| 采购系数 | 0~1 之间的小数（如 0.55） |
| 连通性测试 / 压力测试 | 点「测试与报告」后回填结果 |
| 操作 | 删除 |

- 底部「添加模型」加行；顶部「下载 Excel 模板」/「导入 Excel」可批量
- 填完点「测试与报告」跑测试（本地模拟）
- 最后「保存草稿」→「提交申报」

**这条流程的硬门槛（页面上直接写着）**：

> **「提交须每组至少一个连通成功，整批至少一次有效压力测试」**

也就是：**配置组要有一个通的 + 整批要跑过一次压测**，否则提交不了。
页脚还有个提示「同一草稿可重新测试；每次执行独立留痕」——重测不会顶掉历史。

## 4. 流程 C：内部审批 → 生成接入流程

| 步 | 身份 | 点哪里 | 做什么 |
|---|---|---|---|
| C1 | 领导 | 工作台 或 审批中心 | 看到待审批的申报 |
| C2 | 领导 | 进详情 → 审批 | **同意 / 驳回**；同意时要**指派办理人**（每个节点谁办） |
| C3 | — | 同意后 | 自动生成「供应商接入流程」，状态从"待审批"变"处理中" |
| C4 | 各角色 | 工作台待办 | 被指派的人在自己的待办里看到该节点，「处理」进入办理表单 |

**接入流程的节点结构**（这是理解整个系统的关键）：

```
供应商接入流程
├─ 账户与接口准备（运营）   ┐ 两条并行
├─ 资源配置（运营）         ┘
└─ 合同签署（商务）         ┐ 两条并行（仅首次合作才有）
   └ 授信开具（商务）        ┘  ← 合同不完成，授信不能开始
```

- 节点可以「手动启用」/「沿用已有」（老供应商续做时不重走商务）
- 每个节点办理时要**登记实际办理人**（可多选，可包含不登录系统的线下商务）
- 全部节点完成 → 流程完结 → **通过测试的资源才真正"准入"**，才出现在模型广场的"有可用资源"里

**业务含义**：审批通过 ≠ 能卖。审批只是"同意接进来"，真正能卖要等测试通过 + 合同授信齐。

## 5. 流程 D：客户开通

| 步 | 点哪里 | 做什么 |
|---|---|---|
| D1 | 「客户管理」→ 右上「＋ 创建客户申请」 | 填客户名称（**不能和已有客户重名**）、选报价单、选模型、填指标要求 |
| D2 | 提交 | 进入待审批（客户侧也要审批） |
| D3 | 领导审批通过 | 生成客户开通流程：**合同与授信**（首单才走）+ **账户与资源配置** |
| D4 | 运营办理「账户与资源配置」 | 为每个模型**选一个已准入的供应来源**（同模型 + 同部署节点） |
| D5 | 全部完成 | 客户状态 → 「服务中」，客户详情「接入模型」多出模型行 |

**客户详情（整页 4 个 Tab，不是弹窗）**：

| Tab | 内容 |
|---|---|
| 接入模型 | 列 = 模型名称 / 当前报价系数 / 模型服务状态 / 有效可用资源数 / 已绑定资源数 / 风险·异常；每行可「展开资源」 |
| 档案与办理 | 合同、授信、资质等档案 |
| 该客户报价 | 该客户的报价单 |
| 操作记录 | 留痕 |

**这是整个原型和你们现有系统差距最大的一块**：原型里客户和资源之间有**绑定关系**（一个客户的一个模型，绑到某个供应商的某个资源上，带"已开通/已禁用/供应下架停止"状态），现有系统完全没有这层，客户只靠报价单间接关联。

**几个会拦住你的校验**（可以故意试）：
- 客户重名 → 拦
- 报价里含"不可用或缺完整官方价格"的模型 → 拦
- 已有客户给同一个模型重复申请 → 拦（提示走"客户详情申请新增模型"）
- 指标要求填非数字或超过 100% → 拦

## 6. 流程 E：上下架 / 禁用恢复（最容易被忽略，但业务上最危险）

| 动作 | 入口 | 影响 |
|---|---|---|
| 供应资源下架 | 模型广场 → 详情 → 某行「下架」；或供应商详情 → 「批量下架」 | 该货源停止对客户供给；**已绑定该资源的客户会受影响**（原型里状态变"供应下架停止"，甚至自动归档绑定） |
| 重新上架 | 同上 →「上架」/「批量上架」 | 恢复 |
| 客户资源禁用/恢复 | 客户详情 → 接入模型 → 展开资源 | 停单个客户对某个模型的用量 |

**为什么单独讲**：这几个是**破坏性动作**，会真的把客户服务打断。原型在供应商详情里专门有一块「上下架登记历史」，记 平台模型名称/接口模型ID/操作/时间/操作人/备注——说明这是需要留痕的敏感操作。

## 7. 流程 F：工作台与操作记录

| 看点 | 说明 |
|---|---|
| 待办事项 tab | 4 个状态复选：**待办 / 已办 / 待阅 / 已阅**；可按「人员」筛；列 = 事项 / 业务对象 / 责任人 / 时间 / 状态 / 详情 |
| 「责任人」列 | 有姓名 + 角色两行。「员工」只看到派给自己的，「领导」能看更多 |
| 操作记录 tab | 全站留痕：操作 / 对象 / 操作人 / 时间 / 详情 |
| 底部「演示场景」 | 想快速看某个链路，用这个铺数据，比手点快得多 |

**推荐练法**：先「演示场景」铺一份，然后**换不同身份看同一批数据**——你会立刻明白为什么原型把"角色"做成第一等公民。

## 8. 状态字典（点的时候对一下）

| 对象 | 状态 | 含义 |
|---|---|---|
| 供应资源 | 待接入 / 已接入 / 已下架 | 只有「已接入」能被客户配置 |
| 接入流程节点 | 等待前序交接 / 进行中 / 已完成 | 前一个没完成，后一个是"等待" |
| 客户 | 接入中 / 服务中 | 「服务中」= 4 节点完成且每个模型都选了来源 |
| 客户-资源绑定 | 已开通 / 已禁用 / 禁用待执行 / 恢复待执行 / 供应下架停止 | 禁用/恢复是**待执行**再落地，不是立即生效 |
| 合同状态 | 已归档 / 办理中 / 暂无 | — |
| 合作/商机 | 合作 / 商机 | 底层其实是 已有 / 潜在（有报价=已有） |

## 9. 建议的点击顺序（一次点完，约 20 分钟）

1. 工作台 → 看 4 个状态复选 + 「人员」筛选，认一下 5 个演示成员
2. 标准模型库 → 「＋ 新增模型」→ 只看不存，把 12 个字段看一遍
3. 模型广场 → 进一个模型的「详情」→ 看供应来源表（采购系数/连通耗时/RPS/TPS/缓存命中率/状态）→ 试一次「批量下架」
4. 供应商管理 → 列表（9 列 + 2 个 Tab）→ 进详情看 4 个 Tab，注意「上下架登记历史」
5. **切换到供应商视角** → 登录 → 申报 → 发起申报 → 新建模型申报 → 把「配置组 + 添加模型 + 测试 + 提交」走一遍（**重点**）
6. 切回内部 → 右上身份换成「林舟 · 领导」→ 找审批中心 → 审批刚才那单
7. 客户管理 → 进客户详情 → 4 个 Tab → 「接入模型」点「展开资源」
8. 回工作台 → 「操作记录」看刚才所有动作有没有留痕

## 附：我抓这些时的经验（你可能会遇到同样的问题）

- 这个 HTML 是**多层叠加**的，前几层已被覆盖。页面上看到什么就是什么，**不要去看源码里同名函数的第一处定义**。
- 部分按钮是"权限静默失败"：点了没反应、也没提示。**先确认身份**，再去怀疑页面。
- 右上角身份下拉切换后，页面要重新渲染才生效；如果没变化，切一次导航菜单再回来。
- 供应商视角的登录**不能跳过**：它不继承内部身份，必须手机号 + `1234`。
