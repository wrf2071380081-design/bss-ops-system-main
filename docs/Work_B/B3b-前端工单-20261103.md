## 1. 客户详情整页 4 Tab

### 路由
- 新增 `/internal/customers/:id`，`meta.routeKey` **复用 `internal.customers`**（M8:V），不要新增 routeKey —— 新增要同步 `ROUTE_REQUIREMENTS`，漏配会变成"无权限直接 403"
- `menu: false`，面包屑回列表
- Tab key：`models | onboarding | quotes | records`，URL 同步 `?tab=`，切 Tab 用 `router.replace`（**不要 push**，否则后退会困在 Tab 之间）

### Tab 1 · 接入模型（`models`）
- 数据：`GET /internal/customers/:id/resource-links`
- 列：模型名称 / 当前报价系数 / 模型服务状态 / 有效可用资源数 / 已绑定资源数 / 风险异常
- `risk_flags` 用 tag 展示；`service_state` 为「无可用来源」时整行灰化提示
- **注意**：`service_state` 不会是「接入中」（后端本轮不产出），前端不要为它写特判逻辑

### Tab 2 · 档案与办理（`onboarding`，**deeplink 落点**）
上下两块：
- **上：开通流程**
  - `GET /internal/customers/:id/onboarding`
  - 没流程 → 显示「尚未发起开通」+ 发起按钮（`canAction(CUSTOMER_EDIT)` 才显示）
  - 有流程 → 节点卡（key/status/assignee_name/completed_at/note）+ 模型与绑定列表
  - 节点完成按钮：`CONTRACT` 要**必填说明**、可选填 F12 合同号；`CONFIG` 完成后会写绑定
  - `nodes[].note` 里会出现「F12 就绪能力待客户版 provider 就绪后启用」——**这是正常文案**，不要当错误处理
- **下：合同与授信**
  - 复用 `F12SubjectPanel.vue`（props：`subjectType="CUSTOMER"`、`subjectId=customerId`、`canManage` 按现有 `canManageF12` 逻辑）

### Tab 3 · 该客户报价（`quotes`）
- **只读列表**，数据 `customerWorkspaceApi.quotes({ customer_id })`
- 列：报价编号 / 版本 / 状态 / 生效报价 / 有效期至 / 项数 / 操作人 / 时间
- 「新建报价」按钮：**跳** `/internal/customers?tab=quote&customer_id=<id>`，**不要**把报价编辑器搬过来（那个编辑器 380 行，搬过来就是双份维护）
- 需要给列表页报价 Tab 加 `customer_id` 入参处理（预选关联客户）

### Tab 4 · 操作记录（`records`）
- `GET /internal/customers/:id/operation-logs`
- 列：时间 / 操作 / 操作人 / 说明 / 详情
- `before`/`after` 是 **JSON 字符串**，详情弹窗里格式化展示（`JSON.parse` 失败就原样显示，不要白屏）

### 权限
- Tab 3 可见性：`canAction(PERMISSIONS.CUSTOMER_QUOTE_VIEW)`（**M9:V**）
- 「新建报价」按钮：`canAction(PERMISSIONS.CUSTOMER_QUOTE_EDIT)`（**M9:E**）
- **两者分开判**；纯 M8 角色看不到 Tab 3
- 用 `canAction` 不用 `canRoute`（后者判的是路由 key）

### Tab 加载与缓存
- 每个 Tab **首次进入才请求**，之后切回不重复拉（`loadedFlag` 标记，参考 `SupplierQuoteWorkspace` 的 `historyLoaded` 写法）
- **不要用 `v-if` 在 Tab 之间反复销毁重建**导致每次切换都请求；也不要求 `v-show` 全量预渲染

## 2. 建客户向导（两步）

### 为什么合成一个向导
业务上「建了客户但没开通」= 客户不能用。两个接口分开是后端的事，UI 上必须表达"这两件事要连着做"。

### 结构
- **Step 1 · 客户信息**：`POST /internal/customers`
  字段：客户名称* / 销售归属* / 国内海外* / 结算币种* / 税率 / 账期天数 / 结算方式 / 统一社会信用代码
  - `tax_rate` **按字符串传**（如 `"0.06"`），不要传 number
  - `billing_cycle` 不填就不传（传 0 会 400）
  - `uscc` 小写可接受（后端归一化大写）
  - 重名 → 409，把后端文案原样展示
- **Step 2 · 发起开通**：`POST /internal/customers/:id/onboarding`
  字段：是否首单（默认勾选）/ 合同办理人（首单必填）/ 资源配置办理人 / 模型+来源多行
  - 模型来源候选只显示 `ADMITTED` 且与客户同 `region` 的资源
- 两个请求**各自独立幂等键**（`crypto.randomUUID()`，成功后轮换）

### 失败恢复（必须做，这是重点）
Step 1 成功、Step 2 失败时：
- **保留已创建的 `customerId`**，显示「客户已创建，开通未完成」
- 给两个出口：①「重试发起开通」（复用已建客户，**不要重新建**）②「稍后在详情页处理」→ 跳 `/internal/customers/{id}?tab=onboarding`
- **绝对不允许**让用户从头再来——会再建一个同名客户（后端 409，用户困惑）

### 入口位置
客户列表右上（与现有「新建报价」并列），`canAction(CUSTOMER_EDIT)` 才显示。

## 必须处理的三个坑（来自现状调研）

### 坑 1 · 子 Tab 回弹
`SupplierQuoteWorkspace.vue:49-59` 的 `replaceQuery()` 里有一句守卫 `if (current.tab !== "quote") return;`，注释写着「无条件写回会与父组件 watch 形成回弹」。
**客户详情如果也做"父管主 Tab + 子管子 Tab"，必须复制这个守卫**，否则切回列表会被弹回。

### 坑 2 · 列表筛选返回即丢失
`CustomerWorkspace.vue:45` 的 `filters` 是**纯内存态、无 URL 同步**。做成独立详情路由后，从详情返回列表会重新 `onMounted` → **7 个筛选条件全清**。

**本轮处理**：把 `filters` 落到 `sessionStorage`，列表页 `onMounted` 恢复。
- 不用 query：避免 URL 变脏、分享链接语义变化
- 不做全局 store：筛选是页面级状态，不该跨页面共享
- 要求：点「重置」时同时清 sessionStorage

### 坑 3 · 报价编辑器不搬
`CustomerWorkspace.vue` 的报价编辑器约 380 行（`:97-231` 状态 + `:496-673` 模板），含资源候选分页选择器与 margin/floor 联动。
**只做跳转复用，不复制、不拆组件**——拆组件回归面太大，本轮不值得。
