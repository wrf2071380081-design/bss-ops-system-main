### Task 2：HTTP 与路由

Files: `internal/api/supply_model.go`、`supply_model_request.go`、`router_supply.go`、`supply_model_test.go`。

- 场景：先写真实 Gin/httptest：内部无旧权限点可读，匿名401、其他门户403；写请求拒绝自报维护人、未知字段、重复JSON键、尾随JSON、错误版本类型及缺失PUT字段；成功DTO扁平化并保持ID/金额字符串。
- 场景：写错误映射：领域403/404/409、资料400、缺依赖503、内部错误不回显；历史版本不可编辑。
- 场景：写路由集成：缺幂等键400，同键同body重放不重复调用写服务，同键异body沿用公共400；无存储503。
- 场景：观察红色，实施注册入口 `RegisterSupplyRoutes(group, SupplyDeps)`。组前缀由调用方提供 `/api/internal`，注册器附加内部身份保护，不加旧角色权限点。
- 场景：用严格 JSON 解码及字段存在性校验；重复键不能被 JSON 默认后值覆盖。响应复用现有 response，不在公共源码分配新数字错误码。
- 场景：重跑目标HTTP/领域测试，随后完整 internal/api 包、vet及后端build；更新准确契约和接入说明。

### 验收边界

## plan-only-correction

原型vResourceTable对已有待执行计划显示计划信息/发起人登记，无计划时进入vPlanCreateForm；vPlanForm/vExecutePlan由原发起人登记完成。先前直接登记切片未完整遵循这一入口流程，本次撤下直接状态HTTP路由、writer依赖和处理器、前端直接登记组件/请求及按钮。新增测试断言原直接状态路由404，避免仅隐藏前端后仍能调用。

红色测试（本地运行产物；历史见 Git）证明原服务确实在已有计划/查询失败时仍变更状态；修复后最终验证见：

- vet（本地运行产物；历史见 Git）、build（本地运行产物；历史见 Git）
- 前端回归（本地运行产物；历史见 Git）、类型检查（本地运行产物；历史见 Git）、广场浏览器（本地运行产物；历史见 Git）

## F12、文件与当前办理反例

合同跨页409保留草稿/已上传文件后刷新重试；同档案/授信维度并发只有一份新版本；归档后拒绝修订且历史附件可读。日志写入失败业务整体回滚；资质失败清除新文件，F12保存失败保留独立上传供重试。引用查询失败不删文件，已引用和新文件保留。原发起人/当前节点人员、资源转交后的旧计划资格、BLOCKED409重放及取消/修订后提醒失效按受影响场景补验。Inspector真实调用单独等待配置，不以QA报告或fixture代替。
