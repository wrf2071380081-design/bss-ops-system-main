# F3 资源安全读取与模型广场聚合执行记录

日期：2026-10-20；分支：`feature/supply`。

## 1. 实现范围

- `resource.go`：安全资源快照，绑定模型/供应商/区域/正式配置/报告；逐资源可报价判断；当前报告的毫秒、RPS、TPS字符串指标。
- `resource_cache.go`：报告缓存计数、比例和百分数，使用整数/有理数计算，区分真实零、未提供、不适用及未测试。
- `resource_read.go`：grouped/flat读取端口、筛选校验、完整模型组的聚合、不同分页计数及详情区域检查。
- `supply_resource.go` 与 `router_supply.go`：GET `/api/internal/resources` 和 `/:id` 的独立路由，复用内部人员身份保护、统一响应和错误映射。

可报价要求资源已接入且曾接入、主体有效/区域匹配、模型可报价、有效正式配置且引用版本相符，以及该资源/来源行/目标版本自己的有效连通和压力结论。批次中的其他通过行不能作为依据；配置、测试或模型有阻断时返回具体原因。

草稿阶段报告可以没有 resource_id，但必须匹配本资源来源申报行、行版本和业务身份。目标/行版本变化后原报告标记为STALE，不展示为当前指标，不借用旧缓存命中率。报告原始数据没有被修改。

## 4. 仍需完成

1. A真实仓储需在过滤后的模型集合上分页，再取得所选模型完整成员；不能资源分页后聚合。total/group顺序由SQL负责，单元替身不证明这一点。SQL指标排序使用数值及原始缓存计数，旧目标报告指标视为空，双向NULLS LAST加稳定ID。
2. 资源读取需要同一一致性快照；在C报价/开通写事务中必须加入调用方事务。B适配只在确知未测试时返回空报告，查询失败不能伪装成“未测试”。
3. 资源创建/接入、系数/配置绑定、迟到报告任务顺序、上下架/计划/事件尚未实现；本轮读取保护不是状态写入原子性的证明。
4. B报告历史与人工报告上传仍归B；当前只实现选定报告安全摘要，不提供平行写接口或测试平台模拟成功。
5. 运行中的main/router和新schema未装配，新版广场/资源详情前端尚待实现；不得把独立GET注册器测试称为已部署。
6. 工作台公告/计划子能力和完整A后续范围仍保留，不因本切片完成而缩小目标。
