## 契约与实现

新增 `supplypg.FilterOptionsStore`，实现 `ModelFilterOptionsStore` 和 `ResourceFilterOptionsStore`。构造参数为 *sql.DB，每次调用用一个只读 REPEATABLE READ 事务读取公司和供应商，查询/提交错误直接返回，不冒充空选项。

| 目录 | 公司来源 | 供应商来源 |
|---|---|---|
| F1 标准模型库 | 完整 standard_model，包括尚无资源的模型；公司不因关联资源区域筛选消失 | supplier 与所选区域 resource 的完整关联 |
| F3 模型广场 | 所选区域 resource 关联的标准模型 | 所选区域 resource 关联的供应商 |

资源与供应商区域相同的关系参与查询；供应商不因 FROZEN 被隐藏，目录读取本身不授权其报价。空名称不生成空白选项。关键词对公司、供应商各自名称作字面子串匹配，全部参数绑定，不解释百分号/下划线为通配符。

公司用 DISTINCT，供应商用 EXISTS，先过滤、去重、排序再 LIMIT。每类查询取 Limit+1，分别截断并合并 has_more；公司按名称，供应商按名称、数值ID稳定排序。正式接口端口传入 Limit=50，适配器拒绝0、负数、超过50或非法/重复区域。

该类型只实现真实目录能力，供后续完整模型/资源仓储组合使用。没有为了满足完整读取接口而返回假模型、假资源或空列表；本轮未装配现有 ModelReader/ResourceReader 和生产 HTTP 路由。

| 场景 | 结果 |
|---|---|
| F1 全局公司与多区域供应商 | 无资源公司保留，CN/OVERSEAS组合正确，未关联供应商不混入 |
| F3 区域关系与去重 | CN与OVERSEAS公司集合不同，同供应商多个资源只出现一次 |
