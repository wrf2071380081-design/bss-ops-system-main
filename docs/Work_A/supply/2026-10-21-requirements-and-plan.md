# 三入口需求结论与实施规划

更新日期：2026-10-21。适用范围：开发者 A 的标准模型库、模型广场、工作台子能力及其协作接口。

当前结构实施基线为现有33–36迁移，见[存储映射](./2026-10-21-schema34-baseline.md)与DEC-014。下文早期“先补公共字段”的技术安排由现有列、版本快照及可信事实适配取代；业务结论和页面优先级保留。

本文件是本轮业务需求结论与优先级基线；与早期文档中“全系统无审批”或工作台优先级的表述不一致时，以本文件为准。v0.22 原型继续作为交互与展示依据，已确认的资料完整性、逐资源测试、资源创建时点和上下架计划规则继续有效。

## 1. 人员与操作资格

REQ-01：当前不建立按岗位划分的多级权限体系，不用“模型运营”“采购”等岗位名称直接推断操作权。内部人员能够读取业务资料；具体写操作按记录维护人、归属人、当前办理人或计划原发起人校验。

REQ-02：保留供应商报价的专门审批资格，区分有审批权限和无审批权限的人员。审批资格可以授予人员，不等同于必须建立固定岗位角色。该资格仅授权相应审批动作，不赋予代办其他人员任务、修改其他人模型或代阅公告的权限。

REQ-03：标准模型库、模型广场不新增审批步骤；标准模型人工核验、资源接入登记、计划实际完成登记均是各自业务操作。申报与操作记录保留业务过程证据，不把每一次申报或办理都定义为领导审批。

## 2. 工作台

### 2.1 默认范围与查看他人

REQ-04：工作台默认查看当前登录人员，提供待办、已办、待阅、已阅四种状态。可按姓名切换查询对象；切换人员仅改变所查看的数据，不改变登录身份。本人视图恢复后仍以真实登录人员为操作主体。

REQ-05：普通业务待办、待阅消息及其详情可按姓名切换查看，进入对应业务页面也不因此获得他人权限。目标业务页面必须重新按真实登录主体、该记录当前状态和绑定关系校验，不能信任工作台筛选人员或跳转参数。供应商报价审批候选事项单独按审批资格控制，见REQ-25。

### 2.2 待阅与已阅

REQ-06：进入工作台待阅范围的业务消息面向全部在用内部人员，不按消息所属业务、业务岗位或审批资格缩小范围；每个人都能阅读并处理自己的已阅状态。默认筛选本人只是工作台查询默认值，不代表待办也向全员分发。普通待办仍只绑定一名办理人，供应商报价审批候选事项则仅向有审批资格人员展示。

REQ-07：阅读状态按“待阅事项＋人员”保存。一个人标记已阅不改变其他人的状态；打开详情不自动已阅。查看他人的待阅事项或阅读状态时，仍只能标记当前登录者自己的已阅，不能替被查看者写入状态。重复标记保留首次阅读时间；服务端只从认证上下文取得阅读人。

### 2.3 普通待办与详情导航

REQ-08：每条普通执行待办在任一时点只有一名绑定办理人，只有该人可以完成操作并推进状态；其他人员可以切换到该人员查看待办、查看详情并进入对应业务页面，但不能办理或改变办理人。状态变化后应进入相应人员的已办记录，并保留实际操作者及完成依据。

REQ-09：待办详情进入对应业务界面。执行既有任务不需要再次选择“谁办理当前任务”。“选择办理人”只出现在审批分派后续任务或明确的流程交接动作中；后续任务有自己的办理人，不替换当前任务的认证操作者。

### 2.4 供应商报价审批与任务分派

REQ-10：供应商提交报价后，先产生审批事项，供具有该审批资格的人员处理。该事项属于共享审批候选范围，与单人绑定的普通执行待办分开建模；任一有资格人员完成审批即完成该次审批，不要求所有审批人逐一同意。

REQ-11：审批中选择后续业务办理人；审批完成并保存分派结果后，才生成或激活各指定人员的后续待办。未完成审批与分派前，不向普通人员提前生成可执行的后续任务。资源仍按既有规则在进入办理后创建，草稿不创建正式资源。

REQ-12：共享审批事项必须防止重复决策和重复分派；一名审批人完成后，其他候选人的同一事项不再可处理。保留审批人、审批结果及分派记录。工作台只投影审批事项，决策与分派由供应商报价所属模块负责。

REQ-20：供应商主体新增/注册本身不新增审批；供应商模型新增和价格变更须经过报价审批。供应商提出下架等其他诉求当前线下沟通，不新增供应商自助下架申报审批。这不取消内部资源上下架的计划执行规则。

REQ-21：注册/登录与模型申报解耦。供应商首次申报模型时（此前无模型），进入“测试与资源配置”及“合同与授信”两条适用流程；首次申报可以一次包含多个模型，不能逐行重复建立合同与授信任务。已有模型的供应商申报新模型或改价，仅进入本次适用的测试与资源配置流程。由B提供服务端既有模型及首次办理事实，并处理同时提交的首次批次；不按本次注册/登录入口推断，不跳过尚未完成的实际前置。

REQ-22：价格变更沿用上述审批和指派链路，由审批人选择本次办理人；不固定为原测试人、采购人，也不额外强制创建一个独立改价岗位。该办理人在复用的“测试与资源配置”节点应用已批准价格；节点名称不意味着必须重跑与本次变更无关的全部测试。A只消费B提供的适用节点、办理人及已批准价格事实，不自行创建另一套审批/分派流程。

REQ-23：批次提交自测覆盖全部申报模型的连通性测试，且至少一个模型进行压力测试。该覆盖要求与测试通过结论分开记录，不把“做过测试”改写为“所有测试通过”，也不把批次满足提交门槛等同每个资源已具备接入条件。A逐资源接入仍执行REQ-17；B提交判定的其他已冻结条件继续由B负责。

REQ-24：供应商报价的业务提交者为认证供应商主体，业务链路为“供应商提交 → 有审批资格人员审批并分派 → 指定内部人员办理”。日志可以记录系统动作与内部办理人，但不能把内部办理人显示为供应商报价提交者，不使用页面传入的裸人员ID替代供应商认证身份。

REQ-25：无供应商报价审批资格的人员不展示审批中心入口，也不分发共享审批候选事项；有资格人员看到审批候选和审批操作。隐藏菜单不能代替后端鉴权，直接访问审批路由/API同样按审批资格限制。该专门审批范围不改变普通业务资料全员可读、执行任务仅指定人能办的规则，不在A建立岗位等级体系。

## 3. 标准模型库

REQ-13：资料列用于展示，每行在独立操作列保留单一维护入口。支持公司、模型类型及关联供应商、部署区域筛选，列表排序、分页与空值规则一致。标准模型本身不强加单一区域。

REQ-14：维护八类官方资料、模态、价格条件、计费单位和来源。允许保存不完整资料并明确缺失项；已提供内容仍须合法。资料补齐且人工核验后才能作为报价依据，保存成功或填写核验日期不等于已核验。

REQ-15：新建模型默认维护人为创建者，后续转交使用公共能力；修改按维护人授权及 revision 校验。资料变更保留不可变历史，价格与版本以字符串表达，缺失价格不转换为零价格。自动抓取仍属后续增强，不显示模拟成功。

## 4. 模型广场

REQ-16：按标准模型聚合供应来源，在同一筛选范围内计算供应商去重数、资源数、可用数、系数范围和状态分布；先聚合再分页。展开来源继承筛选范围，详情展示资源、正式配置安全摘要、报告、缓存、计划及操作记录。

REQ-17：每个资源自己的当前有效连通性和压力测试均通过，才能在其他接入条件满足后登记接入及供报价使用。批次允许提交不能替代逐资源准入。A 读取 B 的可信测试、办理与分派事实，不接受页面自报“已通过”“我是办理人”。

REQ-18：报告指标及缓存统计只来自选定报告和匹配目标版本。真实零与缺失分开，不借其他报告的统计，不增加缓存命中率准入阈值；凭据不进入列表、日志或安全快照。

REQ-19：已接入资源上下架采用“创建计划→原发起人登记实际完成”，预计时间只提醒，不自动变更状态。创建、修改或取消计划不直接登记实际完成；实际完成必须核对外部操作和依据，并原子保存状态、日志及相关事件。

## 7. 验收场景

| 编号 | 场景 | 预期 |
|---|---|---|
| W01 | 10名在用内部人员收到一条待阅业务消息 | 每人可读取并有独立未读状态；一人已阅不影响其余9人；待办不会因此广播给全员 |
| W02 | 按姓名查看他人的待阅事项并打开详情 | 允许读取；不自动已阅；只能写当前登录者自己的已阅状态 |
| W03 | 默认进入、切换人员、恢复本人 | 默认本人；查询选择不改变登录主体 |
| W04 | A人员切换到B并查看其普通执行任务、进入业务页 | 可读；服务端拒绝代办，不能修改绑定人员 |
| W05 | 同一报价有两名有审批资格人员 | 任一人完成后该次审批结束，另一人不能再次决策或重复派任务 |
| W06 | 有审批资格者查看他人的后续任务 | 不因审批资格获得代办权 |
| W07 | 报价未完成审批分派／完成后 | 完成前无后续可执行任务；完成后仅分配给指定办理人 |

| W09 | 无模型供应商首次一次提交多个模型 | 主体新增不审批；报价审批分派后按批次产生适用双流程，不逐模型重复合同授信 |
| W10 | 已有模型供应商新增模型或改价 | 报价需审批；改价办理人由审批人指定，不固定原测试人、不新增改价岗位 |
| W11 | 已注册但尚无模型供应商登录后首次申报 | 仍按首次模型流程，不因登录跳过合同授信 |
| W12 | 三个模型仅一个完成连通性测试 | 不满足全模型连通性测试覆盖；至少一个压力测试不能替代其他连通性覆盖 |
| W13 | 全部做过连通性且至少一个做过压力测试 | 满足自测覆盖要求；未通过自身两项测试的资源仍不能接入或报价 |
| W14 | 无审批资格人员访问菜单/审批路由/API | 菜单隐藏，不出现审批候选；后端拒绝审批中心访问和操作 |
| W15 | 供应商报价列表、审批详情与办理记录 | 供应商提交者、审批人、后续办理人分别准确展示 |
| M01 | 不完整模型保存、补齐核验、再修改资料 | 分别待补齐、可供报价、核验失效；历史不变 |
| R01 | 三条申报仅一条测试通过 | 仅该资源在其他前提满足后可接入，其他资源阻断 |
| R02 | 创建未来上下架计划并到期 | 资源不自动改变；仅原发起人确认实际完成后变更 |
