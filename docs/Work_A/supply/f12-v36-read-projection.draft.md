# F12 合同与授信 v36 兼容只读契约（草案）

## 目标与边界

给供应商主体页提供现有 v36 `contract`、`credit_line` 数据的只读投影。该切片不写合同或授信，不迁移运行库，不接客户主体，不调用附件服务，也不作为 B/C 首次接入办理完成或业务 readiness 的依据。

## 现有结构投影

- 合同返回主体、记录 ID、状态、原生 `version`、签署时间、创建/更新时间及 `has_attachment`。不得返回 `file_ref` 或 `note`；`has_attachment` 只表示旧记录存在非空附件引用，不代表可下载或引用有效。
- v36 `contract` 是单行记录并原位更新，没有稳定合同档案键和不可变历史表；因此不得把 `version` 展示为可浏览的版本历史。资料名称、资料编号、来源流程、附件 ID 均不在响应中伪造。
- 授信历史返回主体、记录 ID、方向、币种、金额字符串、原生 `version`、生效/创建时间。列表顺序只用于展示，不决定当前值。
- 当前授信按主体、方向、币种分别选原生最大 `version`。同一维度最大版本有多行时，返回 `AMBIGUOUS_VERSION` 且不返回金额；最大版本金额非正时返回 `INVALID_LEGACY_AMOUNT` 且不作为有效当前额度。没有记录时当前额度列表为空，页面显示“未登记”，不显示 0。
- 显式 `as_of` 以 `created_at <= as_of` 限定候选记录，再按原生最大版本计算；它只用于兼容数据查询，不能补足 v36 缺失的不可变版本保证。

## API

- `GET /api/internal/contracts?subject_type=SUPPLIER&subject_id=...&status=...&page=...&size=...`
- `GET /api/internal/credits?subject_type=SUPPLIER&subject_id=...&direction=...&currency=...&as_of=RFC3339&page=...&size=...`
- 两个入口只允许内部员工身份；主体必须存在。未知/重复查询字段、非法主体、方向、币种、时间或分页参数返回 400。
- 响应提供分页列表和当前授信投影。读取不写操作日志，不自动完成流程。

## 完整 F12 后续依赖

完整合同授信仍需适配共享附件 D07，并提供稳定 `contract_key`、资料名称/编号、`file_id`、来源流程、原因、作者和不可变版本；授信需可并发分配业务版本并具备唯一约束。数据库兼容迁移和 B/C 流程上下文就绪前，禁止通过本只读切片新增或修改记录，也禁止将它接入首次接入完成判断。

## 本切片验收

- 合同和授信仅读取供应商主体现存记录，分页与过滤受服务端校验。
- API/前端不会暴露旧附件路径或备注；并列最大授信版本不会被任意挑选。
- 空主体返回空列表，空授信明确为未登记。
- 主运行库不执行迁移或业务写入。
