编号用于追溯。DEC-020/021覆盖旧的批次自测门槛和草稿物理资源时点；DEC-016覆盖审批中心展示，DEC-018覆盖正式配置加密要求。执行状态及证据不在本文件重复维护，见交接和TDD汇总。

本文件记录用户已明确的选择及其边界。需求和草案仍分别见原始任务材料与模块契约；未列为已确认的建议不能视为用户已批准。

当前业务需求汇总见[2026-10-21需求结论与规划](./requirements.md#requirements)。早期记录中的全系统无审批口径不再适用；以下新增决策明确本轮覆盖范围。

## DEC-001：公共基座与 A 的责任边界

- 日期：2026-10-20。
- 状态：用户已确认。
- 选择：先做 A 的契约和独立业务代码；与 A 任务无关的公共能力由公共负责人补齐。
- 依据：用户回复“可以先做A的契约和独立业务代码。其他的与我任务无关的就由公共负责人补齐”。
- 落地：明确目标 schema、公共装配、事务留痕、绑定及附件/加密依赖；不宣称缺失基座已完成，不以旧业务表或同义临时表替代新表。

## DEC-002：逐资源测试准入

- 日期：2026-10-20。
- 状态：用户已确认。
- 选择：每个资源必须自己的连通性和压力测试都通过，才能登记接入并供报价使用。
- 批次规则：整批申报至少一条通过的提交门槛，不自动赋予其他行接入资格。
- A/B 契约：B 提供对应申报行/目标版本的连通性和压力结论；A 在登记接入时验证自身证据适用性。不能把一个模型的测试结果当作同批其他模型的结果。
- A/C 契约：资源可报价结果必须包含该资源当前有效的测试依据；批次 ID 或批次通过布尔值不能代替逐资源依据。
- 验收：三行仅一行通过时可提交整批；只有该行对应资源可在其他前置满足后接入，另外两行被阻断，且失败不产生成功状态/日志。
- 尚未由本决策确定：测试有效期、测试目标变化判定细则以及已接入资源复测失败的处理。资源创建时机见 DEC-003；不得据此自行增加时效阈值或自动下架规则。

## DEC-003：申报与资源创建时点

- 日期：2026-10-20。
- 状态：用户已确认。
- 选择：申报提交并进入办理后创建 resource；草稿阶段只保留申报行和测试记录。
- B 的测试记录在资源创建前应能关联申报行及其目标版本，不要求草稿先有 resource_id。
- 进入办理时，通过 A 的统一资源创建能力，以 supplier/model/region 及来源申报行防重；根据该行有效测试证据决定待测试或待接入。
- 资源创建不等于接入成功，不使供应商 established 自动变为 true，也不使资源自动可报价。
- B 调用 A 及行 resource_id 回写应共享事务，失败不得出现只有一方完成。
- 尚待核对：目标 DDL 的行/版本关联字段、B 的事务适配签名及申报重试的正式幂等契约。

## DEC-004：标准模型不完整资料可保存

- 日期：2026-10-20。
- 状态：用户已确认。
- 选择：允许将八类资料尚未补齐的标准模型保存为待补齐资料，明确列出缺失项；补齐并由当前维护人明确提交保存核对后才可报价。
- 保存时仍须校验已提供字段的结构和数值合法性；业务资料缺失不等于可以接受非法价格、重复价格项或错误字段类型。
- `missing_fields` 用于定位待补资料；`quote_readiness` 必须阻断缺失资料和未核验模型。
- 最新原型采用单一“保存并留痕”入口：资料不完整时仅保存待补齐/未核验状态；资料完整时，该次由当前维护人发起的保存动作代表其人工核对声明。
- 完整资料保存必须由后端校验维护人、完整性、官方来源、核对日期和 revision，并在一个事务内写入当前版本、不可变快照、核验人和操作记录。修改已核验资料生成新版本；通过本次保存全部校验后新版本才可报价，旧版本和记录保留。
- 单纯字段齐全、填写日期或调用普通创建/更新接口不视为人工核验；缺失价格与有效零价格保持区分。
- 日期：2026-10-23；状态：按用户要求根据最新原型调整实现与契约。

## DEC-011：个人阅读与单人待办

- 日期：2026-10-21。状态：已明确。
- 工作台默认当前人员，按姓名切换只影响查询。进入待阅范围的业务消息面向全部在用内部人员，不因消息业务类型、岗位或审批资格排除；每人可阅读，并独立标记自己的已阅。
- 查看他人的待阅状态或待办时，均不得代替对方写状态。查看待阅内容只允许当前登录人标记自己的已阅；普通执行待办同一时点仅绑定一名办理人，只有绑定人能执行，其他人可查看详情并进入业务页但不得代办或改绑定人。
- 默认筛选本人不等于所有待办都向全员分发。供应商报价审批候选事项仅向有审批资格人员提供，见DEC-012和DEC-015。
- 详情页重查真实登录主体及记录资格，不能用工作台选择人员授权；打开待阅详情不自动已读。

## DEC-015：首次模型、自测覆盖与审批可见性

> 2026-10-27更新：本节早期“全部连通覆盖且至少一项压力”的提交门槛由DEC-020替代；首次分派和逐资源准入规则保留。

- 日期：2026-10-21，按最新业务补充调整。首次双流程以供应商此前是否已有模型判断，与注册/登录解耦；首次可批量提交多个模型，合同授信按适用批次建立。B处理首次并发及未完成前置，A不从浏览器计数猜测。

## DEC-016：审批统一进入领导工作台待办，原流程不变

- 日期：2026-10-23。状态：用户明确确认。
- 产品不再设独立审批中心；供应商报价后的审批事项展示在有审批资格领导的工作台待办区域，详情进入原报价审批及人员分派流程。

- 旧审批中心菜单/路由不再作为产品入口，兼容入口处理和待办详情导航需按当前实现另行对齐，不据需求文档更新宣称已完成代码改造或验收。


## DEC-017：测试凭据分来源，Inspector联调不新增BSS加解密

- 日期：2026-10-23。来源：产品明确供应商自测使用其池子和额度，内部发起测试使用我方平台URL/Key及额度；用户明确本轮不做该测试凭据加密，优先简化多平台联调。
- 供应商一次填写后按Inspector现有接口保存或关联，后续点击复用；是否支持配置ID调用以Inspector真实API为准，不强加解密协议。
- 页面仅显示已配置，Key留空保留；后台可使用保存值调用Inspector，页面不回显不意味着每次重填。日志/错误/报告不记录原Key。
- 供应商自测与内部平台配置及额度来源分开；内部平台Key不得发送到供应商输入的URL。报告保留来源和目标引用，平台自动选源结果不能直接认定指定供应资源通过。
- 本决定针对测试/Inspector链路，未授权批量移除既有正式配置加密或登录密码保护。现有测试加密建议由本决定取代；没有因文档修订修改业务源码、数据库、Inspector或部署。

## DEC-018：正式供应商配置 Key 不做 AES-GCM 加密

- 日期：2026-10-23。状态：用户明确要求移除正式运行配置 Key 的 AES-GCM 加密，以便内部测试链路直接使用已保存配置。
- 本决定仅调整 F4 `supplier_formal_config` 凭据存储：新建和轮换时将 Key 原样保存到现有 000033 物理列 `api_key_enc`；该列名是历史命名，暂不改共享迁移。运行装配不再要求 `MODEL_BSS_FORMAL_CONFIG_KEY_VERSION` 或 `MODEL_BSS_FORMAL_CONFIG_KEY`，也不再构造 AES-GCM sealer。
- API/页面/操作日志继续使用安全投影，不回显 Key；Key 留空更新表示沿用，提供新 Key 才轮换。采购人权限、URL 策略、确认、版本冲突、事务、资源绑定和停用保护继续有效。
- 旧 `se1` 密封值不会自动解密，也不会被当作可用明文；详情显示未配置，修改前要求重新录入 Key。不会借本切片迁移或覆写运行库数据。
- DEC-017 对供应商测试凭据与内部测试凭据来源分离的决定继续有效；DEC-018 只覆盖正式配置凭据。密钥字段改名如需 DDL，按共享迁移维护规则另行协作。

## DEC-019：分阶段批量接入和逐条取消（2026-10-27）

- 多模型选中后逐条校验，返回每条成功/失败；失败条目不回滚其他成功条目。整个批次使用公共幂等事务，每条资源有独立保存点。
- “登记配置完成”记录实际外部配置及有效正式配置引用，不直接开通资源；“确认已开通”要求该目标/资源版本有配置完成事实，并继续逐资源校验正式配置、自身连通性和压力测试及真实办理资格。模型资料不齐仍按既有规则阻止报价，不额外阻止登记接入。
- “取消所选接入”只结束未接入的办理行，保留资源、配置及测试历史，不改变已接入资源；已接入资源仍走下架计划。取消行不能再绑定、接入或发起补测。
- 部分行取消时，其余行继续办理；全部行结束后关闭CONFIG。首次申报全部取消且没有接入行时，关闭未开始的CONTRACT任务，不产生虚假接入或多余商务待办；已有资料保留历史读取授权。
- 配置/开通/取消只由当前B CONFIG指定人员执行，采购归属或查看人员不产生代办权；来源、节点及目标版本在服务端重新读取。内部改价、上下架计划和首次商务授权维持各自边界。

## DEC-020：申报提交采用至少一行有效连通通过（2026-10-27）

- 用户明确选择沿用B当前规则：至少一行连通测试通过且目标未失效即可提交，压力测试不作为提交硬前置；不要求其他行都已完成测试。全部行满足B当前条件进入待审批，否则按B状态机进入待补测试状态，页面如实展示。
- 覆盖DEC-015及旧计划中的“每个模型做过连通、至少一个做过压力”的批次提交规则，避免前端再次按旧口径强制禁用。
- 提交门槛和资源接入门槛分开。任何单条资源登记接入仍需自身连通性、压力测试通过及正式配置/目标版本/办理资格等前提，不借同批其他模型通过结果放行。

## DEC-021：草稿测试资源与正式接管（2026-10-27）

- 用户明确保留B当前草稿发起测试时的物理resource分配，用于test_job等外键；按原唯一维度复用、关联申报行，不将分配视为已批准、已接入或可报价。
- 批准进入办理时，A依据真实批准关联/源行/供应商/标准模型/区域接管同一ID，一次性建立来源和RESOURCE_REVISION控制事实，禁止重复建正式资源或重置已有控制版本。
- A正式资源列表/详情排除有关联申报行但没有正式控制快照的测试专用分配；批准后按正常正式资源规则读取。
- 覆盖旧“草稿绝不写resource”的物理存储限制，不修改逐资源测试与权限门槛；已有正式资源再次申报的复用冲突仍由实际校验决定，不能只按物理唯一键覆盖。
