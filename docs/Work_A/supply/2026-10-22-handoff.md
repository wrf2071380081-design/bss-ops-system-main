## 4. B需提供的真实端口

| 参数/服务 | B侧提供方与责任 |
|---|---|
| `ResourceCreation.LockSource/AttachRow/PrepareReport` | 锁定提交进入办理的来源行/版本，回写资源ID，安全转存草稿报告。共同锁顺序、回写CAS和事务不能跨模块各自提交 |
| `Admission.Proof` | 返回资源对应真实flow/node、办理人、来源/目标版本、前置状态；绑定与接入复用该事实，不按供应商猜流程 |
| `Admission.Report` | 返回自身选定报告、任务序号、来源版本与目标；缺失/失败/旧目标和零指标各自表达 |
| `Admission.CompleteRow` | 逐行完成CAS；不能一条通过就将同批其他资源标记可接入 |
| `TestEvidenceAuthority` | 同事务验证可信B调用及报告关联；HTTP自报测试通过不能成为授权或证据 |
| `PendingConfiguration(ctx, tx, resourceID)` | 已批准未应用变更查询，与批准/应用流程遵守一致资源锁序；失败不能按无变更处理 |
| `module.ResourceCreation / module.TestEvidence` | B在自己的提交办理/回调服务中调用A服务；保留外层事务与真实操作者/RequestID，不给浏览器直接伪造来源 |

批次提交与逐资源准入分开：每个模型做过连通性、至少一个做过压力测试是批次覆盖；每条资源自身连通性和压力测试通过才可接入。资料不完整可登记接入，但阻止报价。B拥有测试平台与报告，不要求重建第二套A报告存储。

A已提供报告列表/详情 API，并在当前源码运行组合中接入 `test_report/test_job` 的 PostgreSQL 读取器。Stage81完成测试时间、测试项、操作人和场景映射，仓储合成数据、API契约及前端场景定向测试通过；Stage83真实登录后的三模块页面/API检查使用的是空主库，没有真实报告业务数据，不能据此写成报告完整联调通过。v36没有可信来源字段，接口必须保持“未记录”，不得推断供应商/内部来源。附件元数据会显示“暂不可下载”，`OpenFile` 不读取 `report_file` 路径、不抓取 `report_url`，实际下载需受控文件存储与授权提供方。B若已有不同报告DTO，由A适配；B仍需提供真实办理节点/选定报告事实以完成资源准入验收。补测当前为办理指引和刷新，不直接启动平台测试。

批准改价已有 `ResourceCoefficientService.Change` 领域端口，**不能据此宣称真实改价仓储/handler/表单完成**。A还需接B批准来源，补完事务适配与实际办理入口；普通资源编辑不得绕过申报批准直接改系数。

## 5. C与公共事件消费者交接

- A资源读取返回 `quote_readiness.eligible/blocked_reasons` 及资源revision、模型版本、配置引用版本；页面旧结果不作为报价授权。C在报价/开通服务中重读可信一致性事实，需要加入自身事务的读取方式由A/C共同对齐，不直接把页面GET当成事务锁。
- 资源接入事件为 `RESOURCE_ADMITTED`，安全payload契约为 `supply.resource_admitted/v1`，见[接入存储契约](./resource-admission-storage.draft.md)。上下架成功发 `RESOURCE_ONLINED/RESOURCE_OFFLINED` 并关联 `RESOURCE_CHANGE` 公告，见[计划存储契约](./plan-storage.draft.md)。提醒使用 `PLAN_REMINDER_SCHEDULED/PLAN_REMINDER_INVALIDATED`。
- 公共outbox写入返回真实事件ID并保留actor/request_id/occurred_at；C按事件ID幂等处理客户影响，影响未知时保持PENDING。上架不自动恢复旧关系；A不直接改写客户关系或历史报价。
- 系数变更的领域事件端口已存在，实际outbox类型/版本及消费者需随H-B04一起冻结；不把尚未装配的事件当成已投递。
