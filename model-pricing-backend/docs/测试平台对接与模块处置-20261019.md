## 一、自动测试平台是什么

一个独立的 **LLM 自动测试平台**，提供 open-api v1。BSS 作为**实名调用方**接入，
供应商给模型自测、以及模型上架后的**复测**，都通过它完成。原型里的
**连通耗时 / 压力 RPS / 压力 TPS** 就来自它的 `summary` 指标。

### 1.1 对接只有四件事

| 动作 | 接口 | 说明 |
|---|---|---|
| 发起任务 | `POST /api/v1/test-jobs` | 带 `Idempotency-Key`；`category` 选门类；`target` 给模型/地址/协议/密钥；`owner` 填供应商 |
| 查进度 | `GET /api/v1/test-jobs/{id}` | 看 `status`、`verdict`、`summary`、`report_dir`；也可 SSE `/events` |
| 下报告 | `GET /api/v1/test-jobs/{id}/report?format=json\|md\|csv\|xlsx` | 终态后可下；`report_retention_days` 后归档 |
| 收回调 | `POST <callback_url>` | 终态推送 `job.completed`，带 `X-Signature`（HMAC-SHA256） |

辅助：`POST /test-jobs/{id}/{action}`（pause/resume/cancel/trigger）、`GET /leaderboard`（智力排行）。

### 1.2 七个测试门类（category）

`health`（健康分，最快）、`baseline`（可用性门控）、`functional`（功能分层）、
`evaluation`（完整 L1~L6）、`intelligence`（智力：AIME/MMLU-Pro）、
`stress`（压测，全局同一时刻只跑一个）、`imagespec`（图片合规）。

### 1.3 关键约束（对接必须遵守）

- **鉴权**：`Authorization: Bearer <实名调用方 token>`；契约面外一律 403。
- **幂等**：同 `Idempotency-Key` + 同 body（SHA-256 逐字节）→ 返回原任务；异体 → 40902。
- **回调**：at-least-once；用 `event_id`（`evt_<job_id>_<status>`）幂等去重；验签用原始 body
  的 `t + "." + body` 做 HMAC-SHA256，时间窗 ±300s。
- **密钥**：`target.api_key` 落库加密、响应只回脱敏值 `api_key_masked`。
- **复测**：`schedule_at` 定时；`review_of` 关联复查来源任务。
- **报告**：长期只保摘要 + `report_url`，报告会归档（归档后 40404）。

### 1.4 与 BSS 原型的字段映射

| 测试平台 | BSS 原型 | 备注 |
|---|---|---|
| `target.base_url` + `target.api_key` | 供应商「正式接口配置」/「测试凭据」 | v0.19 要求**正式配置与测试凭据分开存**；平台用测试凭据 |
| `owner` | 供应商 | 参与评分聚合 |
| `verdict`（pass/fail/abort…） | 资源状态（待测试/已接入/不通过） | pass→可接入；fail/abort→待测试或驳回 |
| `summary`（availability/error_rate/ttft_ms/tpot_ms/sample_count；stress 的 RPS/TPS） | 连通耗时 / RPS / TPS | 原型标注"字段及阈值未定稿"，以平台 summary 为准 |
| `report_dir` / `report_url` | 测试报告 | BSS 存链接 + 摘要，不重复存全量报告 |

## 二、M1–M12 处置建议

> 结论分四档：**保留改造 / 休眠（保留代码与表，隐藏入口） / 下线（不挂路由、移除前端入口，代码与表保留） / 新增**。

| 模块 | 原型对应 | 结论 | 理由 |
|---|---|---|---|
| **M1 模型管理** | 标准模型库 + 模型广场 | **保留改造** | 拆成「标准模型 catalog」+「供应来源 resource」两层，是核心主线 |
| **M2 官方价格同步** | 标准模型库里的官方价/核验 | **保留改造（要自动拉取）** | 确认要做自动拉取；但价格是钱，必须"拉取→暂存/差异→人工确认→生效"，不能静默覆盖。自动抓取任务与暂存区保留，并入标准模型库 |
| **M3 供应商管理** | 供应商管理 | **保留改造** | 加国内/海外主体、接口配置、测试凭据、税率、归属 |
| **M4 报价管理** | 供应商报价/申报 | **保留重写** | 改为「申报（模型新增/价格变更）→ 办理 → 接入」，并接测试平台 |
| **M5 成本管理** | 模型广场的采购系数、报价的毛利 | **大部下线** | 四因子选主供、成本基线、底价公式（÷(1−15%)）原型无；只保留「成本=官方价×采购系数、毛利=1−c/s」计算，可并入 M4/M9 |
| **M6 定价策略** | 无 | **下线/休眠** | 原型用「采购系数 + 销售系数」替代，没有策略引擎 |
| **M7 价目表** | 无 | **下线/休眠** | 原型用「报价单 + 客户开通」替代，没有挂牌价目表发布/回滚 |
| **M8 客户管理** | 客户管理 | **保留改造** | 保留客户主体、销售归属、服务状态、授信、合同、税率；**砍客户自助门户** |
| **M9 客户报价** | 报价单 | **保留改造** | 毛利率↔销售系数双向；补 **Excel 导出**（微信发客户） |
| **M10 财务结算** | 合同与授信 | **大幅缩减** | 账务流水/账单/汇率锁下线；保留「合同 + 授信（带方向/版本）」，可独立成 business 模块 |
| **M11 组织与权限** | 用户切换/销售归属/办理人 | **保留但休眠** | 这一版读取全员可见、操作按绑定；角色权限默认关闭，权限点/中间件保留（注释或开关） |
| **M12 审计** | 操作记录 | **保留** | 绑定操作、二次确认都要留痕 |

### 新增能力（不在 M1–M12）

- **测试平台对接**：test-job 发起/轮询/回调/报告/复测（对接 open-api v1）。
- **合同与授信**（business）：合同签署、授信开具（供应商→我方 / 我方→客户），带版本。
- **变更计划 / 公告**（plan/notice）：上下架计划、采购成本变化公告、资源变动公告。
- **归属/绑定**（assignment）：销售归属、采购人、节点办理人（读取全员可见、操作按绑定）。
- **报价快照/版本**：历史报价保留原样。

## 三、推荐策略：不要物理删除

你的两个选项（"去除" vs "保留等未来"），我的建议是**分三档处理，谁也不硬删**：

1. **必备（继续开发）**：M1、M3、M4、M8、M9、M12 + 测试对接/合同授信/计划公告。
2. **休眠（保留代码与表，入口隐藏、开关关闭）**：M11（权限）。
   （M2 已改为保留改造：要做自动拉取 + 暂存确认。）
3. **下线（不挂路由、移除前端入口，但代码和表保留在仓库/DB）**：M5 的四因子/成本基线/底价、M6、M7、M10 的账务/汇率锁、客户门户。

**理由**：
- 删表/删代码**不可逆**，而未来版本很可能回归（尤其 M10 账务、M6/M7 定价）。
- 用**功能开关（feature flag）**隔离成本最低：路由注册处加 `if features.MX { ... }`，前端菜单同样受开关控制。
- 这样"这一版看不到、用不到"，但"未来一开就回来"，不背技术债。

## 五、一句话总结

**M1/M3/M4/M8/M9/M12 是骨架，保留改造；M2 保留改造（自动拉取+暂存确认）；M11 休眠；M5 大部、M6、M7、M10 大部可下线但别删**。
新增的重点是**接自动测试平台**和**合同与授信**。所有"下线"都建议用开关/注释，不做物理删除。
