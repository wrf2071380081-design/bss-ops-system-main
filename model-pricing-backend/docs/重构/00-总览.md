## 一、已确认口径（所有开发共同遵守）

1. **读取全员可见；操作按绑定人**（销售归属/采购人/办理人），不做角色权限校验。
2. **无审批**。
3. **客户不登录 BSS**；报价导出 Excel 后微信发客户。
4. **定价**：`成本 = 官方价 × 采购系数 c`；`毛利 g = 1 − c/s`；`s = c/(1−g)`；**毛利 <3% 需操作者二次确认并留痕**。
5. **测试由供应商触发**；**整批申报至少一条**连通+压力通过才可提交；**连通失败不能提交**；其他指标不设阈值。
6. **正式接口配置与测试凭据分开存**。
7. **授信 = 额度**（供应商→我方 / 我方→客户），带版本。
8. **标准模型库自动拉取**官方资料（规则+LLM+暂存确认），价格不静默覆盖。
9. **操作记录是一等公民**：每个写接口 同事务写 `operation_log`。
10. 旧模块只隐藏、不删代码和表（feature flag）。

## 一.1 审批口径（2026-10-21 确认）

- **能力**：`SUPPLIER_APPROVAL`，只有 2-3 个领导有；员工只分**领导/普通员工 → 有/无审批权**。
- **存储**：`internal_staff.can_approve_supplier boolean`（不用 capability 表；理由见 `附01`）。
- **审批中心**：**只有领导可见**（普通员工菜单抠掉）；共享队列；**不进工作台待办**（待办只绑一个人）。
- **需审批**：供应商新增模型（对可报价标准模型报价）、价格变更（已投用模型改价）。
- **不需要审批**：供应商注册（新增供应商）。
- **任一领导通过即生效**；驳回必填意见；整批通过/驳回。
- **首个模型**：该供应商**从未有过 `ever_admitted=true` 的资源**；首次申报可含多个模型（每个测连通，至少一个做压力）。
- **通过时领导分配具体员工**：
  - 首个模型 → 测试与资源配置 + 合同与授信；
  - 已有模型的新增/改价 → 只分配测试与资源配置。
- 通过后生成办理节点，任务进入被分配人的工作台待办；申报状态进入办理中。

## 六、协作约定（重要）

1. **接口契约先冻结**：每个功能先在文档里写清 `method/path/入参/出参/错误码`，评审后再写代码。
2. **统一响应包**：沿用现有 `{code,message,data,requestId}`；分页 `{list,total,page,size}`。
3. **写操作必须幂等**：沿用 `Idempotency-Key` 中间件。
4. **留痕**：所有写接口在同一事务调用 `operation_log` 写入 helper（公共模块提供）。
5. **绑定校验**：操作前校验当前人是否是 `sales_id/buyer_id/assignee_id`；不通过返回 403。
6. **平台维度**：列表/校验都要带国内/海外；不能跨区域报价/开通。
7. **开关**：新接口不受旧开关影响；旧接口下线用 `features`（已实现）。
8. **分支**：每人一条 feature 分支；接口契约变更先在群里同步，再改。
9. **不删旧代码/旧表**：只加开关或新增表。
