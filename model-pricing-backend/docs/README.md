## 文档维护约定

1. **一个事实只写一处**：口径写在设计文档，操作步骤写在运维/用户手册，不要互相复制。
2. **改行为必须同步改文档**：涉及发布流程、接口、界面文案的改动，PR 里同时改文档。
3. **过期即归档**：一次性报告完成后归档，不要留在根目录。
4. **不写"将来会"**：只写已经生效的行为；计划项写到待实现清单。
