## 〇、三个硬阻塞（不解决，页面就是 404/500）

1. **路由没挂**
   - `internal/api/router_supply.go` 里 `RegisterSupplyRoutes` 写好了，但主路由的
     `registerSupplyRoutes(g, protected, portal, deps)` 是**空函数**（只判断 portal）。
   - `RegisterSupplyRoutes` 只在 `_test.go` 里被调用；`main.go` 没有构造 `SupplyDeps`。
   - 结果：`/api/internal/standard-models`、`/api/internal/resources` 在集成环境不存在。

2. **没有生产仓储**
   - `ModelReadStore`、`ResourceReadStore` 只有接口，`supplypg` 里没有实现；
     测试用的是 `supplyHTTPReadStore` 假 store。
   - 就算挂路由，list/detail 也没有真实数据源。

3. **真实表缺 A 代码依赖的列**
   - `standard_model` 缺：`verify_status`、`maintainer_id`、`revision`、`version_no`、`checked_by`。
   - `resource` 缺：`revision`（CAS 用）。
   - `plan` 缺：`revision`、`expected_resource_revision`（计划修订/执行用）。
   - `f1_schema.go` 只是"契约检查器"（注释明确写了 not a migration），不会补列。

> 这三条不补，标准模型库/模型广场的按钮全部不可用；前端截图里的数据来自测试/mock。

## 一、标准模型库：逐按钮

### 1. ＋ 新增模型
| 项 | 内容 |

| 期望 | 打开维护弹窗，填官方资料，保存后生成 V1 |
| 现有 | `POST /standard-models` 代码在 `RegisterSupplyRoutes`，**未挂载**；writer 无生产实现 |
| 缺 | 生产 writer（单事务：insert standard_model + version + operation_log） |
| 字段 | company、name、official_id、model_type、input/output_modalities、capacity、abilities、price_items、api_access、lifecycle、sources、checked_at、status、maintainer_id、revision、version_no、verify_status、checked_by |

## 二、模型广场：逐按钮

### 1. 搜索 / 公司 / 类型 / 部署节点 / 供应商 / 资源状态 + 查询/重置
| 项 | 内容 |
|---|---|
| 现有 | `GET /resources?view=groups` + `/filter-options` 代码；**未挂载、无 store** |
| 缺 | `ResourceReadStore` 生产实现：先按模型分页，再取该页模型的全部资源聚合 |
| 字段 | `resource.standard_model_id/supplier_id/region/state/coefficient`；`standard_model.company/model_type/name/official_id` |
| 逻辑 | 过滤在 SQL；聚合（supplier_count/resource_count/available_count/coefficient min/max/state_counts）在 domain；`available_count` 还要满足"模型已核验 + 资源 ADMITTED + 可报价" |
| 索引 | `resource(standard_model_id, region, state)`、`resource(supplier_id, state)`、`resource(coefficient)`；`standard_model(model_type)`、`(company)` |

### 2. 排序：名称 / 公司 / 供应商数 / 可用资源数 / 系数下限
| 项 | 内容 |
|---|---|
| 现有 | 白名单已校验 |
| 缺 | 聚合排序的索引/物化 |
| 逻辑 | 供应商数/可用资源数/系数 min 是聚合值，不能直接走 resource 单列索引；当前量小可实时聚合，量大建议 **物化视图** `mv_resource_plaza`（按模型预聚合 + 索引 sort 列） |
| 索引 | 物化视图上建 `(supplier_count)`、`(available_count)`、`(coefficient_min)`、`(name)` |

### 3. 详情（行）→ 供应来源弹窗
| 项 | 内容 |
|---|---|
| 现有 | `GET /resources/:id`、`/resources?view=rows` 代码；**未挂载、无 store** |
| 缺 | 生产 store；弹窗里的资源操作按钮 |
| 逻辑 | 按 `standard_model_id` + 当前筛选（region/supplier/state）取行；每行带最新 `test_report` 指标与 `quote_readiness` |
| 索引 | `resource(standard_model_id, region, state)`；`test_report(resource_id, tested_at DESC)`（已有） |

### 4. 供应来源表排序：供应商 / 系数 / 连通 / RPS / TPS / 缓存命中率
| 项 | 内容 |
|---|---|
| 现有 | 白名单允许这些字段；实际排序在 SQL/domain |
| 缺 | 缓存命中率排序没有可用索引 |
| 逻辑 | 连通/RPS/TPS/缓存来自"该资源最新一条 test_report"；缓存命中率 = `cache_hit_tokens / cache_input_tokens` |
| 索引 | 指标排序建议把"最新报告"的指标**反范式到 resource**（`latest_connection_ms/latest_rps/latest_tps/latest_cache_hit_rate`），再建索引；否则要 lateral join + 表达式排序，无法走索引 |

### 5. 资源操作：下架 / 登记接入 / 上架 / 补测
| 项 | 内容 |
|---|---|
| 现有 | 领域层 `resource_state.go` 只支持 **OFFLINE / ONLINE**；`resource_coefficient.go` 支持改系数；**HTTP 没有 `/resources/:id/state` 处理器/路由**（只有测试引用了这个路径） |
| 缺 | ①状态 HTTP handler + 路由；②`登记接入`（ADMIT）属 B 的申报/办理，不在 A 的状态服务；③`补测`属 B 的测试触发；④前端弹窗没有这三个按钮 |
| 字段 | `resource.revision`（CAS，**表里缺**）、`state`、`ever_admitted`、`buyer_id`、`latest_test_report_id` |
| 逻辑 | OFFLINE 仅 `ever_admitted=true && state=ADMITTED`；ONLINE 仅 `state=OFFLINE`；计划冲突检查（PENDING/EXECUTING 的 ONLINE/OFFLINE）；操作人必须是 `buyer_id`；写 operation_log + 事件 |
| 索引 | `resource(state, updated_at)`、`resource(buyer_id)`（已有）、`plan(resource_id, status, due_at)` |
| 权限 | 现在 `requireSupplyInternalStaff` 只校验"内部员工"，**没校验 buyer 绑定**；状态/改系数必须加 `buyer_id = 当前人` 的校验 |

### 6. 查看报告（N）/ 报告详情
| 项 | 内容 |
|---|---|
| 现有 | **没有报告列表/详情接口**；弹窗只显示最新指标和缓存命中率列 |
| 缺 | `GET /resources/:id/reports?page=&size=` + `GET /reports/:id`（返回指标、场景、文件 URL） |
| 字段 | `test_report`：connection_ms/passed、stress_passed、rps/tps、availability、error_rate、ttft/tpot、sample_count、verdict、report_url/format/file、scene、tested_at、cache_hit_tokens/input_tokens |
| 逻辑 | 报告可多条；`resource.latest_test_report_id` 指最新；列表按 `tested_at DESC` 分页 |
| 索引 | `test_report(resource_id, tested_at DESC)`（已有）；`verdict` 过滤可加 `(resource_id, verdict, tested_at DESC)` |

### 7. 上架 / 下架计划
| 项 | 内容 |
|---|---|
| 现有 | 领域 `plan_lifecycle.go` + HTTP create/revise/cancel 代码；**未挂载**；**执行接口没有**（A 报告里也写了未做） |
| 缺 | ①生产 plan store；②`POST /plans/:id/execute`；③前端计划弹窗/列表；④`plan.revision`、`expected_resource_revision` 列 |
| 字段 | plan：resource_id、kind(ONLINE/OFFLINE/PRICE_CHANGE)、reason、due_at、before/after jsonb、status、created_by、revision、expected_resource_revision |
| 逻辑 | 创建时快照 before/after；修订/CAS；执行时再校验 resource.revision + 状态；冲突 → BLOCKED + 409 |
| 索引 | `plan(resource_id, status, due_at)`、`plan(created_by, status, created_at DESC)` |

## 三、表/索引补齐建议（DDL 草案）

```sql
-- 1) 补 A 代码依赖的列（先与 A 确认类型/默认值）
ALTER TABLE standard_model
  ADD COLUMN IF NOT EXISTS maintainer_id bigint,
  ADD COLUMN IF NOT EXISTS revision      bigint  NOT NULL DEFAULT 1,
  ADD COLUMN IF NOT EXISTS version_no    integer NOT NULL DEFAULT 1,
  ADD COLUMN IF NOT EXISTS checked_by    bigint,
  ADD COLUMN IF NOT EXISTS verify_status varchar(16) NOT NULL DEFAULT 'INCOMPLETE';

ALTER TABLE resource ADD COLUMN IF NOT EXISTS revision bigint NOT NULL DEFAULT 1;
ALTER TABLE plan
  ADD COLUMN IF NOT EXISTS revision bigint NOT NULL DEFAULT 1,
  ADD COLUMN IF NOT EXISTS expected_resource_revision bigint;

-- 2) 草稿允许 official_id 为空：部分唯一索引
DROP INDEX IF EXISTS uk_standard_model_company_official;
CREATE UNIQUE INDEX uk_standard_model_company_official
  ON standard_model(company, official_id) WHERE official_id <> '';

-- 3) 搜索/排序
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX IF NOT EXISTS idx_standard_model_name_trgm
  ON standard_model USING gin (name gin_trgm_ops);
CREATE INDEX IF NOT EXISTS idx_standard_model_official_trgm
  ON standard_model USING gin (official_id gin_trgm_ops);
CREATE INDEX IF NOT EXISTS idx_standard_model_checked_at ON standard_model(checked_at DESC);
CREATE INDEX IF NOT EXISTS idx_standard_model_updated_at ON standard_model(updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_standard_model_verify_status ON standard_model(verify_status);
CREATE INDEX IF NOT EXISTS idx_standard_model_maintainer ON standard_model(maintainer_id, updated_at DESC);

-- 4) 广场聚合/筛选
CREATE INDEX IF NOT EXISTS idx_resource_model_region_state
  ON resource(standard_model_id, region, state);
CREATE INDEX IF NOT EXISTS idx_resource_supplier_state ON resource(supplier_id, state);
CREATE INDEX IF NOT EXISTS idx_resource_coefficient ON resource(coefficient);

-- 5) 指标反范式 + 缓存命中率
ALTER TABLE resource
  ADD COLUMN IF NOT EXISTS latest_connection_ms numeric,
  ADD COLUMN IF NOT EXISTS latest_rps numeric,
  ADD COLUMN IF NOT EXISTS latest_tps numeric,
  ADD COLUMN IF NOT EXISTS latest_cache_hit_rate numeric;
CREATE INDEX IF NOT EXISTS idx_resource_latest_cache ON resource(latest_cache_hit_rate DESC);

-- 6) 计划 / 通知 / 抓取
CREATE INDEX IF NOT EXISTS idx_plan_creator_status ON plan(created_by, status, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_plan_resource_status ON plan(resource_id, status, due_at);
CREATE INDEX IF NOT EXISTS idx_notice_read_staff ON notice_read(staff_id, read_at DESC);
CREATE INDEX IF NOT EXISTS idx_crawl_job_status_next ON crawl_job(status, next_run_at);
CREATE INDEX IF NOT EXISTS idx_crawl_job_model_created ON crawl_job(standard_model_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_crawl_diff_model_status ON crawl_diff(standard_model_id, status, created_at DESC);
```

> `verify_status` 现在是 domain 计算值，不是列。要在列表"筛选/排序"里用它，必须落列并在保存/核验时维护，否则只能全量取回内存算，分页会错。

## 四、自动抓取（先定方向，不展开）

- **频率**：每天定时（worker，例如 03:00 Asia/Shanghai），按厂商限流；失败退避重试。
- **任务**：`crawl_job(standard_model_id, source_url, status, attempt_at, success_at, error, raw_hash)`；
  `crawl_diff(field, old_value, new_value, source_url, quote, confidence, status)`。
- **官方信息不足**：先做规则适配器（厂商 API/文档页）；结构化不足时，未来接大模型抽字段。
  LLM 只产出"候选值 + 证据引用 + 置信度"，**不直接覆盖**，进 `crawl_diff` 等人工确认。
- **价格绝不静默覆盖**：价格类 diff 必须人工确认；非价格类可配置低风险自动接受（后续再说）。
- **列表展示**：`standard_model` 加 `last_crawl_status/last_crawl_at/last_success_at`，避免每行查 job。
- **索引**：见上面 DDL 第 6 段；`crawl_diff` 建议 `UNIQUE(crawl_job_id, field)` 防重复。

## 六、一句话

**标准模型库 / 模型广场不是"还差几个按钮"，而是"页面有了、domain 有了，但生产仓储、表列、路由三样都没接"。**
先做 P0 的六件事，这两个页面才算真正能用；P1 再补资源操作与报告；自动抓取按"每天定时 + 差异确认 + 未来 LLM"单独排期。
