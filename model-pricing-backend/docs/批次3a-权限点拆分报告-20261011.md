## 1. 问题与方案

`M5:E`（成本管理·编辑）在 `000007_seed` 里被 6 个角色持有，但它实际承载三个完全不同的动作：

- 成本参数配置（`PUT /cost/params`）→ 只应是 PRICING_OP
- 主供应商锁定（`POST /cost/baselines/:sku/lock-primary`）→ 只应是 PROCUREMENT
- 汇率锁定（批次 6 待建）→ 只应是 FINANCE

中间件 `RequirePerm(M5:E)` 只看权限点、无法区分角色；此前全靠服务层 `CanEditCostParam` /
`CanLockPrimary` / `CanLockFx` 兜住，**权限点层面的授权是过宽的**
（MODEL_OPS / RETRO_OP 持 M5:E 属历史遗留越权，无对应职责）。

方案（不新增操作码，沿用字典内既有的 C / E）：

- 成本参数配置 `M5:E` → **`M5:C`**（仅 PRICING_OP）
- 主供应商锁定 保留 **`M5:E`**（仅 PROCUREMENT）
- 汇率锁定 `M5:E` → **`M10:E`**（仅 FINANCE）

## 4. 验收实测（启动后端打真实 HTTP，`localhost:8080`）

判读口径：

- `403 / 10003 无权限` = 被第一层 `RequirePerm` 拦住（缺权限点）
- `403 / 10003 角色 [...] 不含 PRICING_OP…` = 过了第一层、被第二层服务层角色收敛拦住
- `400 / 10001` = **两道门都过了**，因 body 故意非法（缺 `overrides` 键 / `supplier_id=0`）而报参数错
  —— 用非法 body 是为了**零业务写副作用**

结果（重新登录后，快照 perms 已含新授权）：

- `smoke_admin`（PLATFORM_ADMIN+MODEL_OPS+PRICING_OP，持 M5:C=Y / M5:E=Y）
  - 改成本参数：**400 请求缺少 overrides 字段** → 两道门都过 ✅
  - 锁主供应商：403「角色 [PLATFORM_ADMIN MODEL_OPS PRICING_OP] 不含 PROCUREMENT」 → 服务层拦住 ✅
- `smoke_bursty`（PRICING_OP，M5:C=Y / M5:E=N）
  - 改成本参数：**400** ✅；锁主供应商：403 无权限 ✅
- `buyer_a`（PROCUREMENT，M5:C=N / M5:E=Y）
  - 改成本参数：403 无权限 ✅；锁主供应商：**400 supplier_id 必须 >0** → 两道门都过 ✅
- `smoke_finance`（FINANCE，M5:C=N / M5:E=N）
  - 改成本参数：403 ✅；锁主供应商：403 ✅
  - 注：迁移前 FINANCE 持 `M5:E`，改参数会走到服务层才被拒；现在第一层就拒了 —— **权限点收窄生效的实证**
- `smoke_sales`（SALES）：两项均 403 ✅
- `tmp_mops_3a`（MODEL_OPS 单角色，M5:C=Y / M5:E=N）
  - 改成本参数：403「角色 [MODEL_OPS] 不含 PRICING_OP，不允许修改成本参数（M5:C 服务层角色收敛）」 ✅
  - 锁主供应商：403 无权限 ✅
- `tmp_retro_3a`（RETRO_OP 单角色）：两项均 403 无权限 ✅

`ValidateInDB`：后端启动日志**无 permission point mismatch** ✅

> `tmp_mops_3a` / `tmp_retro_3a` 是本批为实测临时建的账号（库里没有纯 MODEL_OPS / RETRO_OP 账号），
> 测完已连 `login_session` / `role_grant` / `internal_staff` / `account` 一并删除。

## 6. 新增测试与变异验证

`pkg/perm/perm_test.go` 新增 3 个（任务书要求"锁住各角色对三个动作的允许/禁止集合"）：

- `TestCostActions_ExactlyOneRoleEach`：每个动作（成本参数配置 / 主供应商锁定 / 汇率锁定）

## 9. 残留风险（本批未处理）

- **`MODEL_OPS` 仍持 `M5:C`**：`000007_seed` 给了 M5 除 A 外全权限。当前 `M5:C` 只挂了成本参数
  一个接口，且该接口服务层要求 PRICING_OP，故 MODEL_OPS 实际仍改不了（实测 403 已证实）。
  但按 B1 的约定「后续新增参数/策略配置类接口应挂 `:C`」，届时 MODEL_OPS 会自动获得，
  **需在那时候一并收敛**。任务书未授权本批清理，已在迁移注释中标注。
- **`PLATFORM_ADMIN` 单角色账号改不了成本参数**：它持 `M5:C`，但服务层 `CanEditCostParam`
  只认 PRICING_OP。这是 06-cost.md §11-1 既有设计（本批未改），`smoke_admin` 因同时持有
  PRICING_OP 不受影响。
- **纯 `MODEL_OPS` / `RETRO_OP` 账号库里原本没有**，本批靠临时账号实测，测完即删；
  后续若要常态化回归，建议在种子里固化一个。
- **汇率锁定接口**属批次 6；`000030` 已把 FINANCE 的动作迁到 `M10:E`，批次 6 实现时应挂 `M10:E`。
