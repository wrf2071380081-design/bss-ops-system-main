共 4 条反馈，逐条定位根因并修复。文档内截图本环境无法读取，结论全部由文字反馈 + 真库核对得出。

## 反馈 1：官方价变更单卡在第 2、3 步

**现象**：变更单走到第 2 步（财务审批）、第 3 步后再无进展。

**根因（不是后端缺陷，是入口缺失）**：后端 `POST /api/internal/approvals/{target}/decision`
一直存在且按 `change_type` 分发到不同审批服务；但前端 `OfficialPriceSync.vue` 的变更单抽屉
是**纯只读**的——只渲染了步骤条，没有"通过 / 驳回"按钮，审批人根本无处可点，单子自然停住。

**修复（前端）**

- `src/api/changeRequests.types.ts`
  - 新增 `isChangeRequestDecidable(status)` 与 `CHANGE_REQUEST_DECIDABLE`（`PENDING / CONFIRMING / APPROVING`）。
  - 新增 `DecideChangeRequestRequest{stepNo, decision, comment}` 与 `DecideChangeRequestResultDTO`。
- `src/api/changeRequests.ts`：新增 `decide(target, body)`，幂等 scope 用
  `change-request:decision:{id}:step:{stepNo}`——**按步骤分键**，否则第 2 步与第 3 步共用一个键会被幂等中间件吞掉第二次请求（这正是"卡在第 3 步"的另一半原因）。
- `src/modules/pricing/views/OfficialPriceSync.vue`
  - 抽屉内新增审批区：通过 / 驳回按钮 + 审批意见 textarea + 毛利预演表 + 公式提示。
  - 列表「操作」列宽 90 → 150，加「审批」按钮。
  - 按钮可用性由 `isChangeRequestDecidable(status)` 控制，已终态的单不再显示审批入口。

**未验证项（如实说明）**：本地库当前无处于 `PENDING/CONFIRMING/APPROVING` 的真实变更单，
`decide()` 的端到端只做到类型检查 + 构建通过，未做真库点按。变更单查询接口后端尚未提供，
本页仍只回显本次建单结果。

## 反馈 2：供应商报价提交后不能撤回

**裁决口径**：**允许审批完成前撤回** → `VOIDED`。已审批 / 已生效的单**不**可撤回
（撤回等于推翻他人决策或改写历史，属另一条业务流）。

**修复（后端新增接口）**

```
POST /api/supplier/quotes/{id}/withdraw
Idempotency-Key: <uuid>
{ "reason": "output 组件价格填错，撤回重提" }   // 整体可省略
```

- 新增 `internal/domain/supplier/withdraw.go`：`ErrQuoteNotWithdrawable`、
  `ErrQuoteWithdrawReasonTooLong`、`IsWithdrawableStatus`（**白名单** SUBMITTED/APPROVING）、
  `WithdrawInput/Result/Params`、`(*QuoteService).WithdrawQuote`。
- `QuoteStore` 增 `WithdrawQuote`；`internal/repo/supplier_quote.go` 实现：
  - 条件更新 `UPDATE quote_sheet SET status='VOIDED' WHERE id=? AND supplier_id=? AND status IN ('SUBMITTED','APPROVING')`。
    **归属与状态一次判完**，不做"先查后改"（TOCTOU + 漏一处即越权）。
  - `todo_task` OPEN → `DONE`（审批人不该再看到它）。
  - `audit_log(action='QUOTE_WITHDRAW', reason=<撤回原因>)`，同事务。
- 错误映射：状态/归属不合 → **409**（与审批侧 `ErrQuoteNotApprovable` 同口径；
  「不是自己的单」与「状态已推进」同码，避免用 403/404 差异泄露他人报价单 ID 是否存在）；
  原因超长 → 400。
- 路由挂在供应商门户段，**不挂 `RequirePerm`**（SUPPLIER 角色零内部权限点），挂幂等中间件。
- `reason` 选填（≤500 rune），与驳回（10~500 必填）刻意不同——撤回是处置自己的数据，不该被长度卡住。
- `VOIDED` 不在 `FindNonTerminalQuote` 的非终态集合里 → **撤回后可立刻重新提交**。

**修复（前端）**

- `src/api/quoteContract.ts` 新增 `withdraw(id, reason?)`。
- `src/views/supplier/SupplierQuoteList.vue`：列表「操作」列与详情抽屉各加「撤回」按钮，
  `canWithdraw(status)` 与后端白名单同口径；弹出输入框填原因（选填，≤500 字校验）。

## 反馈 3：毛利预演显示不满足仍可通过

**裁决口径**：**不硬拦截**（市场行情倒挂时合法业务仍需放行），但**强制填理由**并留痕。

**修复**

- `internal/domain/supplier/approve.go`
  - 新增 `ErrQuoteMarginCommentRequired` 与 `ApproveInput{Comment}`；`Approve()` 增加入参。
  - 空审批意见时先 `Diff()` 再判 `HasMarginViolation()` → 命中则返回 400，**不落库**。
  - `HasMarginViolation()` 口径：只有 `margin_ok == false` 算不满足；
    `margin_ok == null`（无官方价参照，**无法判断**）**不算**，否则会把参照数据缺失的单子也逼着填理由。
  - 判定放服务层而非前端：UI 只能提示，绕过前端直接调接口同样要拦；且复用 `Diff()` 同一份计算，
    避免"页面说满足、后端说不满足"。
  - 理由写入 `audit_log.reason`（`quote_sheet` 无审批意见列），可被审计页检索。
- `internal/api/quotes.go`：绑定可选 body（`ContentLength > 0` 才 bind）；错误映射 400。
- 前端 `src/views/internal/supplierQuotes/SupplierQuoteList.vue`：
  - 抽屉顶部告警（不满足 → error 级；无法判断 → info 级）。
  - 「通过整单」改为先弹填写理由对话框；不满足时理由必填，填了才发给后端。
  - 后端 400 的错误信息原样展示（用户能看到为什么被拒）。

**顺带修掉同一条反馈里的「floor 推算公式未知」**

- 根因：`FloorPrice` 直接用 `decimal.Div` 的原始结果（DivisionPrecision=16），
  前端原样显示成 `2.3529411764705882` 这种长串——审批人看到一个来路不明的长数字，自然会问"公式是什么"。
- 修复：`StringFixed(8)`（与契约 §14 示例 `2.35294118` 一致）。**判定用未舍入的精确值**，
  避免四舍五入把边界情况判成满足；只有展示串取 8 位。
- 新增 `cost_basis`（成本基准＝本明细行首个组件供应价）与 `formula`
  （常量 `floor = 供应价 ÷ (1 − min_gross_margin)`），审批页新增两行展示，能自证 floor 怎么来的。

## 反馈 4：基础模型库新建 SKU 后需录官方价

**裁决口径**：**保持分离设计**（SKU 档案请求体不含价格，这是既定的主数据口径），
不把价格塞进新建表单；改为**保存成功后引导**到官方价同步页，并带上新 SKU 预填。

**修复（前端）**

- `src/modules/models/views/Models.vue`
  - `save()` 成功后捕获新建返回的 `id`，弹出引导框说明官方价三步流程，
    确认后 `router.push({ path: "/internal/official-prices", query: { new_sku, sku_code, currency } })`。
  - 取消引导不视为失败——单子已经建好，引导只是下一步提示。
- `src/modules/pricing/views/OfficialPriceSync.vue`
  - `onMounted` 读 `?new_sku=`，`applyNewSkuGuide()` 校验 `^[1-9]\d*$` 后设置 `newSkuGuide`。
  - 页面顶部显示三步引导告警（可关闭）。
  - 预填「新建采集批次」表单的 SKU（有模型查看权限走多选选择器，没有则走手工 ID 输入）。
  - 打开「录入暂存价格」时首行预填该 SKU + 币种。
  - `skuLabel()` 增加 `guidedSkuLabels` 兜底：新建的草稿 SKU 还没被列表接口收录，
    只显示确实拿到的编码，**不伪造厂商/系列**。

## 真库验收（本地 docker `model_bss_pg`，后端实起 8080）

后端起服务 → HTTP 全流程 → 当场 kill。

- `supplier_a` 登录 → `POST /supplier/quotes` → `id=164, v10, APPROVING`。
- `POST /supplier/quotes/164/withdraw`（带幂等键 + 原因）→ **200**，`status=VOIDED`。
- 库里核对：
  - `quote_sheet 164`：`status=VOIDED`
  - `todo_task`（`biz_type='QUOTE', biz_id=164`）：`status=DONE`
  - `audit_log`：189 `QUOTE_SUBMIT`、190 `QUOTE_WITHDRAW`（`reason=价格填错，撤回重提`，`operator_role=SUPPLIER`）
- **二次撤回** → **409** `报价单状态不允许撤回（仅审批完成前可撤回）`。
- **跨供应商**：`supplier_b` 撤 164 → **409**；且 `QUOTE_WITHDRAW` 审计总数 = **2**，
  两条 `operator_id` 都是 1（supplier_a）——**越权尝试零写**。
- **撤回后可重提**：改价格重提 → `id=165, v11, APPROVING` → 再撤回 → `VOIDED`。
  证明确实没被非终态互斥挡住。
- 内部 `GET /internal/quotes/pending` 列表不含 164（VOIDED 不进审批队列）。
- `max(quote_sheet.id) = 165`，无幻影行。

**手工改库声明：无。** 未执行任何手工 `UPDATE` / `DELETE`。
真库新增 2 条报价单（164 / 165，均为 `VOIDED`），全部由 HTTP 接口产生，保留作为验收证据；
副作用是 `supplier_a` 的 `version_no` 已推进到 11。

## 遗留与待裁决

- **`APPROVED_PENDING`（已批准未生效）不可撤回**：本次按裁决没做。若产品认为需要，
  属"撤销审批"另一条业务流，需单独定义审批人是否可撤销自己的结论。
- **撤回不发事件**：`event_outbox` 目前没有 withdraw 事件类型，下游（开放接口订阅方）
  感知不到"某报价被撤回"。如需感知要新增事件类型并同步 §11 文档。
- **新建 SKU 引导未做权限分支**：没有 `PRICE_SYNC` 写权限的账号跳过去后看不到录入按钮，
  引导文案仍会显示。要不要按权限裁剪文案，待产品确认。
- **反馈 1 的 `decide()` 未做真库点按**：本地库无处于可审批态的变更单，需在有数据的环境补一次手测。
