## 2. 发布

### 2.1 一条命令

```bash
bash scripts/deploy.sh 20261125-r18      # 标签可省略，默认 日期-r提交数
```

脚本做 6 件事，任何一步失败都会中止（且前后端版本不一致会自动回滚后端）：

```
0. 守卫：git status 必须干净（否则版本戳不可信，直接拒绝）
1. 构建后端：GOOS=linux GOARCH=amd64 CGO_ENABLED=0，-p=4，-ldflags "-s -w"，注入 sha/buildAt
2. 构建前端：每次都建；注入 <meta name="build-sha">；删除 dist/mockServiceWorker.js
3. 上传：server.gz + dist.tar.gz → /tmp
4. 切换：备份旧二进制 → 替换 → 解到 releases/<tag> → 切 current → 重启
5. 自证：/api/version 的 sha 与 index.html 的 build-sha 都必须等于 HEAD
6. 不一致：回滚后端 + 退出码非 0
```

### 2.2 可选参数

| 变量 | 作用 |
|---|---|
| `SKIP_BACKEND=1` | 只发前端（后端产物不构建、不上传、不自证） |
| `SKIP_FRONTEND=1` | 只发后端 |
| `BUILD_P=1` | 并发编译数，默认 4；受限环境崩了就降到 1 |

### 2.3 耗时基线（2026-11-25 实测）

```
构建（前后端并行）   29~33s
上传                 200~240s   ← 瓶颈，见 §6
切换/重启/自证       10~15s
合计                 ~4 分钟
```

**上传为什么慢**：到测试服务器实测只有 **0.8 Mbps（约 100 KB/s）**，15.5MB 的 gzip 包就要 155 秒。想快只能减少上传量（服务器端编译）或提带宽。

### 2.4 回滚

```bash
# 后端（脚本自证失败时会自动执行）
ssh dapp@10.19.218.33 'sudo cp $(cat /tmp/last-good-server) /app/model_bss/bin/server && sudo systemctl restart model-bss'

# 前端：切回上一个 release
ssh dapp@10.19.218.33 'ls /app/model_bss-web/releases | tail -3'
ssh dapp@10.19.218.33 'ln -sfn /app/model_bss-web/releases/<上一个> /app/model_bss-web/current'
```

### 2.5 版本自证

```bash
curl -s http://10.19.218.33:8081/api/version          # {"sha":"...","built_at":"..."}
curl -s http://10.19.218.33:8081/ | grep build-sha     # 必须与上面一致
```

两个不一致，说明只发了一端——**这是历史上最容易发生的故障**。

## 3. 数据库迁移

服务器上**没有 migrate CLI**，全部手工执行；`schema_migrations` 只有一行。

```bash
# 1) 先看远端仓库最大编号！多人并行开发时编号冲突会造成"迁移漏执行"
git fetch origin main && git ls-tree origin/main model-pricing-backend/migrations --name-only | sort | tail -3

# 2) 传文件并执行（必须单事务 + ON_ERROR_STOP）
scp migrations/0000NN_xxx.up.sql dapp@10.19.218.33:/tmp/
ssh dapp@10.19.218.33 'chmod 644 /tmp/0000NN_xxx.up.sql'
ssh dapp@10.19.218.33 'sudo -u postgres psql -d model_bss -v ON_ERROR_STOP=1 --single-transaction -f /tmp/0000NN_xxx.up.sql'

# 3) 更新版本号（不 dirty）
ssh dapp@10.19.218.33 'sudo -u postgres psql -d model_bss -c "UPDATE schema_migrations SET version=NN, dirty=false"'
```

**纪律**：

- 编号冲突是**已经发生过一次线上 500** 的原因（两个 000072）。写迁移前必须先 fetch 看远端最大号。
- 迁移不幂等（例如 000053 假设手机号空闲），在有历史数据的库上重跑会撞唯一键。
- 服务器上的 `/app/model_bss/migrations` 是旧副本（只到 000048），**不要以它为准**。

## 4. 配置与开关

### 4.1 模块开关（feature gate）

`internal/infra/middleware/feature.go` 里约 46 条路由按 `config.features` 决定是否 404。

```yaml
features:
  approval: true
  legacy_price_sync: true
  special_price: true
  cost: false
  pricing_policy: false
  price_upconduction: false
  supplier_quote_approval: false
  finance_legacy: false
  customer_portal: false
```

**坑**：`config.yaml` 里如果没有 `features` 段，9 个开关全是 false → **46 条路由全部 404**，看起来像"代码没发上去"。启动日志会打印模块清单，全关时额外告警。

### 4.2 压测模板

```yaml
test_platform:
  stress_template: "bss压力测试02"
```

启动时向测试平台拉模板参数（时长/并发档位/目标 RPS），日志会打印：

```
{"msg":"stress template loaded","template":"bss压力测试02","duration":"60s","concurrency":[100],"load_mode":"open"}
```

**取不到模板时压测直接 503，不再静默兜底**——兜底参数（30s/并发1）曾让慢模型测出 0 TPS。

### 4.3 附件存储（本地 / 腾讯云 COS）

合同与授信附件有两种后端，靠环境变量切换，**数据库里的 `file_id` 不变**：

```ini
# 默认：本地目录
MODEL_BSS_ATTACHMENT_DRIVER=fs
MODEL_BSS_F12_ATTACHMENT_STORE_DIR=/app/model_bss/var/f12-attachments

# 对象存储（推荐）：密钥只放 env，不进 config.yaml、不进仓库
MODEL_BSS_ATTACHMENT_DRIVER=cos
COS_SECRET_ID=...
COS_SECRET_KEY=...
COS_REGION=ap-guangzhou
COS_BUCKET=cos-bucket-asset-bss-1254396208
```

线上做法：`/app/model_bss/configs/cos.env`（600 root）+ systemd drop-in：

```ini
# /etc/systemd/system/model-bss.service.d/cos.conf
[Service]
EnvironmentFile=-/app/model_bss/configs/cos.env
```

**切换是零停机的**：切到 cos 后，新文件写 COS，历史文件继续从本地目录读（`F12AttachmentFallbackStore` 兜底）。因此本地目录**在迁移完成前不能删**，且必须进备份。

对象命名与本地一致（`<key>.blob` / `<key>.json`），迁移只需按 key 上传，不需要改库。

### 4.4 nginx

```nginx
location = /index.html { add_header Cache-Control "no-store, must-revalidate"; }
location /assets/     { add_header Cache-Control "public, max-age=31536000, immutable"; }
client_max_body_size 8m;   # 附件走 base64，2MiB 文件编码后约 2.7MiB
```

`index.html` 必须 no-store，否则发版后浏览器仍加载旧 chunk，表现为"改了没生效"。

## 5. 故障排查手册

| 现象 | 根因 | 处理 |
|---|---|---|
| 发版后界面没变化 | 浏览器缓存了旧 index.html | 强刷 Ctrl+F5；确认 `Cache-Control: no-store` 已生效 |
| 工作台/列表 500 | 迁移漏执行（编号冲突、只跑了一个） | 对比 `schema_migrations` 与仓库编号，补执行 |
| 大量接口 404 | `config.yaml` 缺 `features` 段 | 补齐开关后重启 |
| 登录 401 | `login_id` 用错（内部是手机号，不是拼音） | 查 `account.login_id` |
| 上传附件 413 | nginx `client_max_body_size` 太小 | 改 8m 并 reload |
| 附件丢失 | `var/f12-attachments` 未备份 / 被清理 | 从备份恢复；纳入定期备份 |
| 平台上"看不到"我们发的任务 | 发单被 40001 拒绝（如 target.protocol 不该传） | 看 `test_job.failure_reason`，页面已直出平台原文 |
| 压测 0/0 TPS | 单请求耗时 ≥ 吞吐窗口（如 60s 窗口 + 32k prompt） | 提高时长档位；报告里的 `throughput_bias_note` 会说明 |
| 状态一直"待测试" | 报告 `category` 与查询条件不匹配（历史用 baseline，现用 protocolprobe） | 确认视图 SQL 已包含 protocolprobe |
| 连通性显示"通过"但平台判 fail | 前端/接口用了旧的"有报告即通过"兜底 | 只认 `submission_row.connectivity_status`（PASS/FAIL） |
| 报价里看不到资源 | `quote_readiness.blocked_reasons` 非空 | 看资源详情"当前阻断项"，按提示补资料/配置/测试 |
| 编译崩 `0xc0000409` | 受限沙箱拦截 `compile.exe`（非真并发问题） | 用 `BUILD_P=1`；正常终端下 `-p=4` 实测 8.7s 通过 |
| GitHub 连不上 | 解析到不通的 IP（多个 A 记录） | 跑 `scripts/github-hosts-heal.ps1`（需管理员）切换 hosts |

## 6. 已知限制（不要在文档里假装没有）

1. **单机无灰度**：`systemctl restart` 有 1~3 秒中断。
2. **前端不能自动回滚**：脚本只回滚后端，前端靠手工切 `releases/`。
3. **上传带宽 0.8 Mbps**：全量发布约 4 分钟，其中 3 分钟在传文件。
4. **无 CI**：`gofmt / go build / vue-tsc` 靠本地自觉执行。
5. **测试库版本可能超前仓库**：同事直接改过测试库（如 078~082）。发布前先对齐分支，别只信 `schema_migrations`。

## 7. 备份与恢复

```bash
# 数据库
sudo -u postgres pg_dump -Fc model_bss > /opt/backups/model_bss_$(date +%F).dump

# 附件（必须）
sudo tar czf /opt/backups/f12-attachments_$(date +%F).tar.gz -C /app/model_bss/var f12-attachments

# 测试报告
sudo tar czf /opt/backups/test-reports_$(date +%F).tar.gz -C /app/model_bss/bin test-reports
```

建议保留 7 天。当前备份散落在 `/tmp`，**机器重启即丢**，应统一到 `/opt/backups` 并加清理策略。
