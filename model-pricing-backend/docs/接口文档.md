# 接口文档

> 本文只写**约定**与**主链路**。完整字段定义以 `/swagger/index.html`（后端启动后）与 `internal/api` 下的路由注册为准。
> 最后更新：2026-11-25

## 1. 门户与鉴权

平台只有**两个**门户，没有客户登录：

| 门户 | 前缀 | 谁用 |
|---|---|---|
| 内部 | `/api/internal` | 平台运营、采购、定价、财务、审批人 |
| 供应商 | `/api/supplier` | 供应商账号 |

客户相关功能（报价单、合同授信）目前由**内部代客操作**，`features.customer_portal=false`，前端不挂 `/customer` 路由。

### 1.1 登录

```
POST /api/internal/auth/login      {"login_id":"13900002001","password":"..."}
POST /api/supplier/auth/login      {"mobile":"...","password":"..."}
```

- **内部账号的 `login_id` 是手机号**，不是拼音（历史坑，见运维手册）。
- 成功返回 `data.token`，后续请求带 `Authorization: Bearer <token>`。
- `POST /api/internal/auth/logout`、`POST /api/supplier/auth/logout` 注销。
- 会话存在 `login_session`，token 是会话哈希，**改角色/改权限需要重新登录**才会生效（快照在登录时生成）。

### 1.2 权限

代码层保留了细粒度权限点（`pkg/perm`，形如 `M1:V`），但**业务上不再按功能模块细分角色**，实际以「角色 + 数据域」为准：

- 数据域：`ALL`（看全部）/ `SELF`（只看自己负责的）
- 供应商门户不挂功能权限，靠 `supplier_id` 做行级隔离

接口文档因此**不逐个标注权限点**；需要确认某接口对谁开放，看路由注册里的 `RequirePerm(...)` 或该 handler 内的角色判断。

## 2. 通用约定

### 2.1 响应包

```json
{ "code": 0, "message": "ok", "data": { }, "requestId": "uuid" }
```

- `code = 0` 表示成功；非 0 见 §2.4
- `requestId` 每次请求唯一，排障时让对方提供这个值

### 2.2 分页

```json
{ "list": [], "total": 123, "page": 1, "size": 20 }
```

参数统一 `page`（从 1 开始）、`size`（默认 20，最大 100）。

### 2.3 幂等

写接口要求带幂等键：

```
Idempotency-Key: <客户端生成的唯一串>
```

- 同键同体 → 回放上次响应
- 同键异体 → `409`
- 前端约定：一次业务动作一个键（如"提交审批"点两次不会产生两条记录）

### 2.4 错误码

| code | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | — |
| 10001 | 参数校验失败 | 看 `message`，通常是字段名 |
| 10002 | 未认证 / token 失效 | 重新登录 |
| 10003 | 无权限 | 换账号或补授权 |
| 404xx | 资源不存在 | — |
| 409 | 状态冲突 / 幂等冲突 / 乐观锁（`expected_revision` 不匹配） | 刷新后重试 |
| 503 | 依赖未就绪（测试平台未接入、压测模板未加载） | 看服务日志 |

## 3. 主链路接口

### 3.1 供应商申报

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/supplier/submissions` | 申报列表 |
| POST | `/api/supplier/submissions` | 新建草稿 |
| GET | `/api/supplier/submissions/:id` | 详情（行 + 连通性状态 + 报告摘要） |
| PUT | `/api/supplier/submissions/:id` | 保存草稿（`expected_revision` 必填） |
| POST | `/api/supplier/submissions/:id/tests` | 发起连通性测试；`{category:"CONNECTIVITY", group_id?}`，带 `group_id` 即只测该组 |
| GET | `/api/supplier/submissions/:id/test-progress` | 测试进度（前端 1~3 秒轮询，只更新状态字段） |
| POST | `/api/supplier/submissions/:id/rows/:rowId/test` | 单行补测 |
| POST | `/api/supplier/submissions/:id/submit` | 提交申报（**门禁：所有行连通性必须 PASS**） |
| POST | `/api/supplier/submissions/:id/withdraw` | 撤回（仅待审批/待测试） |

**提交门禁**：任一行 `connectivity_status != PASS` 时返回 `409`，`message` 里带未通过的模型名。

### 3.2 审批与流程

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/internal/flows/submissions/:id` | 审批视图（行、测试状态、节点、办理人） |
| POST | `/api/internal/flows/submissions/:id/...` | 审批/分配/办理动作（按 `node_key` 区分技术/商务） |
| GET | `/api/internal/flows/suppliers/:id/progress` | 供应商办理进度（技术 N/M、商务状态） |

审批节点与角色绑定在 `onboarding_node.required_role`，**接口本身不做功能权限校验，靠节点角色**。

### 3.3 测试

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/internal/resources/:id/tests` | 内部补测（`category`: `connectivity` / `stress`） |
| GET | `/api/internal/resources/:id/reports` | 报告列表 |
| POST | `/test-callback` | 测试平台回调（无需登录，**尚未做签名校验**，上线前必须补） |

压测参数**只来自平台模板**（`test_platform.stress_template`）；模板取不到返回 `503`，不会静默兜底。

### 3.4 资源接入与可报价

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/internal/resources` | 资源列表（`view=flat` 平铺） |
| POST | `/api/internal/resources/:id/formal-configs` | 绑定正式接口配置 |
| POST | `/api/internal/resources/:id/admit` | 登记接入（→ `ADMITTED`） |
| GET | `/api/internal/resources/:id` | 详情，含 `quote_readiness` |

`quote_readiness` 结构：

```json
{
  "eligible": true,
  "blocked_reasons": [],           // 阻断报价的硬性问题
  "warnings": ["MODEL_NOT_READY"], // 不阻断，仅提示（如标准模型资料不全）
  "resource_revision": "4",
  "model_version_no": "7",
  "formal_config_revision": "1"
}
```

**硬阻断**（`blocked_reasons`）：未接入、正式配置不可用/已变更、无有效测试报告、测试依据失效、供应商停用、区域不匹配。
**软提示**（`warnings`）：标准模型资料不全/未核验。

### 3.5 客户报价（内部代客）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/internal/customer-quotes/candidates` | 可报价资源候选（只返回 `eligible=true` 的资源） |
| POST | `/api/internal/customer-quotes` | 建报价单（`APPLY`/`CLONE`/`TEMP` 三种来源） |
| POST | `/api/internal/customer-quotes/:id/submit-approval` | 提交审批 |
| POST | `/api/internal/customer-quotes/:id/...` | 审批/生效 |

报价单价目有 **floor 硬校验**：任一 `unit_price < 完全成本/(1-最低毛利率)` → `409`，须走特价审批。

### 3.6 配置组与凭据

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST/PUT | `/api/supplier/test-config-groups` | 准入测试配置组（URL + API Key） |
| GET/POST | `/api/supplier/attachments` | 合同/授信附件上传（≤2MiB，落 `var/f12-attachments`） |
| GET | `/api/supplier/attachments/:id` | 下载（鉴权 + 审计） |

## 4. 变更约定

1. **新增字段向后兼容**：只加不改；删字段必须升版本并同步前端。
2. **改语义必须改文档**：例如"可报价"的判据变化，要同时改本文 §3.4 与 UI 规范。
3. **错误码不复用**：新场景给新码，不要借 409 表达其它含义。
4. 完整字段以 swagger 为准；本文负责"为什么这样设计、有哪些坑"。
