# 000033_target_model 迁移说明（2026-10-20）

## 做了什么

新增 **30 张表**，按 Token Ops v0.19 原型重做的目标数据模型。**只建新表，不动旧表**。

| 分组 | 表 |
|---|---|
| 主数据 | standard_model、standard_model_version、crawl_job、crawl_diff |
| 供应商 | supplier、supplier_formal_config、supplier_qualification |
| 供应来源与测试 | resource、test_job、test_report、webhook_event |
| 申报与办理 | submission、submission_row、submission_version、onboarding_flow、onboarding_node、onboarding_batch |
| 客户与开通 | customer、customer_link |
| 报价与合同授信 | quote、quote_line、quote_version、contract、credit_line |
| 变更与公告 | plan、notice、notice_read |
| 操作留痕 | operation_log、assignment_log、margin_override |

## 命名避让

旧表已占用 `supplier_profile / customer_profile / customer_quote / quote_item / audit_log / credit_txn` 等，
所以新表刻意避开：
- 报价行用 `quote_line`（不是 `quote_item`）
- 授信用 `credit_line`（不是 `credit`）
- 人员沿用 `internal_staff`，**不重建 staff 表**

## 关键约束

- `resource`：`UNIQUE(supplier_id, standard_model_id, region)`；`CHECK(coefficient > 0 AND coefficient <= 1)`
- `customer_link`：`UNIQUE(customer_id, resource_id) WHERE archived = false`
- `quote.customer_id NOT NULL`（报价单客户不可为空）
- `quote_line`：`margin < 1`、`0 < discount <= 10`
- `operation_log` 索引 `(entity_type, entity_id, created_at DESC)`

- `schema_migrations`：version=33，dirty=false
- 30 张表全部存在；27 个外键；6 个唯一索引；3 个部分唯一索引

## 怎么应用

```bash
migrate -path migrations \
  -database "postgres://app:***@127.0.0.1:5433/model_bss?sslmode=disable" up
```

回滚一步：`migrate ... down 1`。

## 注意

- 兼容 **PostgreSQL 14+**（线上 14.24），未用 PG15 专有语法。
- `resource.latest_test_report_id ↔ test_report.resource_id` 是循环外键：
  up 用后置 `ALTER TABLE` 加约束；down 先 `DROP CONSTRAINT` 再删表。
- 未改动 `internal_staff` 及任何旧表；旧表与新表可并存。
- 本地库已应用到 version 33（开发库）。
