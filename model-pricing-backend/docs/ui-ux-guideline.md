# UI / UX 规范

> 只写**已经在用**的规则，不写设想。所有值来自 `src/styles/tokens.css` 与现有页面实践。
> 最后更新：2026-11-25

## 1. 颜色

### 1.1 基础色板（`tokens.css`）

| 语义 | 变量 | 浅色 | 深色 |
|---|---|---|---|
| 页面底色 | `--app-bg` | `#f3f6fa` | `#101721` |
| 卡片/面板 | `--app-surface` | `#ffffff` | `#18212e` |
| 次级底 | `--app-surface-muted` | `#f7f9fc` | `#1e2938` |
| 描边 | `--app-border` | `#e3e9f1` | `#334155` |
| 主文字 | `--app-text-primary` | `#24324a` | `#e5ebf4` |
| 次文字 | `--app-text-secondary` | `#56657a` | `#bdc9d9` |
| 弱文字 | `--app-text-muted` | `#79869a` | `#92a1b7` |
| 主色 | `--app-accent` | `#5266df` | `#9daaff` |
| 成功 | `--app-success` | `#299f81` | `#5bc4a8` |
| 警告 | `--app-warning` | `#c48724` | — |
| 危险 | `--app-danger` | `#d65362` | — |

**规则**：新代码只用变量，不写字面色值。深色模式由 `html.dark` 覆盖，硬编码颜色会失效。

### 1.2 状态色的固定语义

| 状态 | 颜色 | 用于 |
|---|---|---|
| 通过 / 已完成 / 已接入 | success（绿） | 连通性通过、审批通过、资源已接入 |
| 未通过 / 失败 | danger（红） | 连通性未通过、审批驳回 |
| 提示 / 待补 | warning（黄） | 可用于报价但有待补项、失效报告 |
| 中性 / 未开始 | info（灰） | 未测试、排队中、已取消 |

**一个状态只能有一种颜色**，不允许同一含义在不同页面用不同色。

## 2. 字体与字号

```css
font-family: Inter, "Segoe UI", "Microsoft YaHei", sans-serif;
```

| 用途 | 字号 |
|---|---|
| 页面主标题（模型名/主体名） | 22px |
| 次级标题 | 16~18px |
| 正文、表格 | 13px |
| 辅助说明（muted） | 12px |
| 角标/单位 | 11px |

数字（金额、TPS、RPS、耗时）统一使用等宽数字（`font-variant-numeric: tabular-nums`），避免列宽跳动。

## 3. 布局与间距

- 侧边栏宽 `--app-sidebar-width: 244px`
- 面板内边距：16px；面板间距：16px；区块内元素间距：8px / 12px
- 表格：`min-width` 按内容给，**不要用固定宽度导致换行**
- 抽屉（详情）：宽 880px，右侧滑出；弹窗（表单）：宽 640~880px

## 4. 组件用法

| 场景 | 组件 | 约定 |
|---|---|---|
| 状态 | `el-tag` size="small" | 颜色按 §1.2；**不要自造标签样式** |
| 提示 | `el-alert` | `warning` 用于"能做但有风险"，`danger` 用于"做不了" |
| 空态 | `el-empty` | 文案写"还没有 X，点 Y 开始"，不要只写"暂无数据" |
| 加载 | 转圈（`el-icon.is-loading`） | **只替换单元格内容**，不要整表骨架屏 |
| 危险操作 | `el-popconfirm` / 二次确认 | 删除、撤回、下架必须确认 |

## 5. 交互硬规则（都是踩过坑的）

1. **刷新不重建整表**：轮询只更新变化字段（`Object.assign(row.test, next)`），行对象引用保持稳定，否则整表闪烁。
2. **切主体必清状态**：切换资源/供应商时，重置表单与派生字段（`connectivity_status` 之类不能跨主体继承）。组件用 `:key` 强制重挂载。
3. **测试类任务显示"测试中"转圈**，出结果再换成红/绿；不要显示"已完成"这种含糊状态。
4. **可报价判定只信后端**：前端不再自行组合 `passed/verdict/report_id`，避免同一状态两种结论。
5. **发版后不要求用户强刷**：`index.html` 必须 `no-store`。

## 6. 文案词表

统一用词，避免同义多写：

| 概念 | 用词 | 不要用 |
|---|---|---|
| 连通性结果 | 通过 / 未通过 / 测试中 / 未测试 | 已完成、未判定、失败（与"未通过"混用） |
| 阻断 | 当前阻断项（不可报价） | 风险、异常 |
| 非阻断提醒 | 可用于报价，但有以下待补项 | 警告、提示（不指明范围） |
| 资源状态 | 待测试 / 已测试 / 已接入 / 已下架 | 待接入（易与"已测试"混） |
| 测试门类 | 连通性测试 / 压力测试 | L1、baseline、comprehensive（内部代号不外露） |

**英文枚举一律不出现在界面上**：走 `src/domain/labels.ts` 映射，未知值原样返回但不加颜色。

## 7. 数值与格式

| 类型 | 规则 |
|---|---|
| 金额 | 保留 2 位小数，右对齐；货币符号跟随配置 |
| 采购系数 | 保留 4 位小数（`1.0000`），不要省略尾零 |
| TPS / RPS | 2 位小数；为 0 且报告标注"窗口过短"时，旁边加说明 |
| 时间 | `YYYY/MM/DD HH:mm`；表格里秒级可省略 |
| 百分比 | 2 位小数 + `%`；后端给 0~100，不要重复乘 100 |

## 8. 禁止事项

1. 不要用颜色作为唯一信息载体（色盲不可辨）——必须配文字。
2. 不要在表格里塞多行长文本（会把行高撑乱），改抽屉/弹窗展示。
3. 不要在前端"猜测"业务状态（例如"有报告就算通过"），一律以后端字段为准。
4. 不要新增 `已完成` 这类中间态；状态要么是结果，要么是进行中。
